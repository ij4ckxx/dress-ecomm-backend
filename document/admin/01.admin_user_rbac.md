# Module 01: Admin RBAC & User Management API

> **Module:** 01 - Admin RBAC & User Hierarchy  
> **Audience:** Frontend Development Team  
> **Base URL:** `/api/v1/admin/users` (or `/api/admin/users`)  
> **Auth Required:** `Authorization: Bearer <accessToken>`  

---

## 1. Overview & Business Rules

This module manages administrative staff, store managers, and customer accounts under a **strict hierarchical delegation system**:

1. **Role Hierarchy:**
   - `SUPER_ADMIN` (Level 4): Master root admin. Can create & manage `STORE_ADMIN`, `STAFF`, and `CUSTOMER`.
   - `STORE_ADMIN` (Level 3): Store manager. Can create & manage `STAFF` and `CUSTOMER`.
   - `STAFF` (Level 2): Warehouse/Operations worker. Can create & view `CUSTOMER`.
   - `CUSTOMER` (Level 1): Regular buyer. Cannot access any `/admin/*` routes.
2. **Permission Delegation:**
   - Higher levels define what lower levels can do.
   - A `STORE_ADMIN` can only assign permissions that they themselves possess.
   - `SUPER_ADMIN` has full access to all features automatically.
3. **Deactivation & Editing Guard:**
   - An admin cannot edit or deactivate an account with an equal or higher role than their own.
   - An admin cannot deactivate their own account.

## 2. Frontend Role-Based UI Guidelines

Use the user's role from your Auth store to control UI visibility:

| Role | Users Page Access | "Create Store Admin" Button | "Create Staff" Button | "Create Customer" Button |
| :--- | :---: | :---: | :---: | :---: |
| `SUPER_ADMIN` | Full | Visible | Visible | Visible |
| `STORE_ADMIN` | Staff & Customers | Hidden | Visible | Visible |
| `STAFF` | Customers only | Hidden | Hidden | Visible |
| `CUSTOMER` | Blocked (Redirect) | Hidden | Hidden | Hidden |

## 4. API Endpoints Specification

### 4.1. Get Delegatable Permissions
Fetches the permissions the current logged-in user can assign to subordinates.

- **Endpoint:** `GET /api/v1/admin/users/permissions/delegatable`
- **Headers:** `Authorization: Bearer <token>`
- **Response `200 OK`:**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Delegatable permissions fetched successfully",
  "data": {
    "permissions": [
      "products:read",
      "products:write",
      "inventory:read",
      "inventory:write",
      "orders:read",
      "orders:write"
    ]
  }
}
```

---

### 4.2. Create Subordinate User
Creates a new down-level user (`STORE_ADMIN`, `STAFF`, or `CUSTOMER`).

- **Endpoint:** `POST /api/v1/admin/users`
- **Headers:**
  - `Authorization: Bearer <token>`
  - `Content-Type: application/json`
- **Request Body:**
```json
{
  "name": "Priya Sharma",
  "email": "priya.staff@maison.com",
  "password": "Password123!",
  "role": "STAFF",
  "phone": "+91 98765 43210",
  "permissions": [
    "products:read",
    "inventory:read",
    "orders:read",
    "orders:write"
  ]
}
```
- **Validation Rules:**
  - `name`: String, 2 to 100 characters (Required).
  - `email`: Valid email string (Required).
  - `password`: Min 8 characters, at least 1 letter, at least 1 number (Required).
  - `role`: One of `"STORE_ADMIN"`, `"STAFF"`, `"CUSTOMER"` (Required).
  - `phone`: Optional string.
  - `permissions`: Optional array of valid permission strings.
- **Response `201 Created`:**
```json
{
  "success": true,
  "statusCode": 201,
  "message": "STAFF user created successfully",
  "data": {
    "user": {
      "id": "cuid_or_uuid_123",
      "name": "Priya Sharma",
      "email": "priya.staff@maison.com",
      "role": "STAFF",
      "permissions": [
        "products:read",
        "inventory:read",
        "orders:read",
        "orders:write"
      ],
      "phone": "+91 98765 43210",
      "isActive": true,
      "createdById": "admin_uuid_456",
      "createdAt": "2026-10-08T18:00:00.000Z"
    }
  }
}
```

### 4.3. List Users (Paginated with Search & Filters)
Retrieves users visible to the current admin.

- **Endpoint:** `GET /api/v1/admin/users`
- **Headers:** `Authorization: Bearer <token>`
- **Query Parameters:**
  - `page`: Page number (Default: `1`)
  - `limit`: Items per page (Default: `20`, Max: `100`)
  - `role`: Filter by `"STORE_ADMIN"`, `"STAFF"`, `"CUSTOMER"`
  - `search`: Case-insensitive search across name, email, or phone
  - `isActive`: `"true"` or `"false"`
- **Example Request:**
  `GET /api/v1/admin/users?page=1&limit=10&role=STAFF&search=priya`
- **Response `200 OK`:**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Users fetched successfully",
  "data": [
    {
      "id": "cuid_or_uuid_123",
      "name": "Priya Sharma",
      "email": "priya.staff@maison.com",
      "role": "STAFF",
      "permissions": [
        "products:read",
        "inventory:read",
        "orders:read"
      ],
      "phone": "+91 98765 43210",
      "isActive": true,
      "createdById": "admin_uuid_456",
      "creator": {
        "id": "admin_uuid_456",
        "name": "Store Admin One",
        "role": "STORE_ADMIN"
      },
      "createdAt": "2026-10-08T18:00:00.000Z",
      "updatedAt": "2026-10-08T18:00:00.000Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 1,
    "totalPages": 1
  }
}
```

- **Headers:**

## 5. Common Error Responses for Frontend Handling

| Status Code | Error Code | When It Happens | Frontend Action |
| :--- | :--- | :--- | :--- |
| **`400 Bad Request`** | `VALIDATION_ERROR` | Missing required fields or password too short. | Display inline field errors on form. |
| **`400 Bad Request`** | `CANNOT_DEACTIVATE_SELF` | Admin clicked "deactivate" on their own account. | Show alert: "You cannot deactivate your own account." |
| **`401 Unauthorized`** | `UNAUTHORIZED` / `INVALID_TOKEN` | Token is expired, invalid, or missing. | Clear token & redirect user to `/login`. |
| **`403 Forbidden`** | `FORBIDDEN_NOT_ADMIN` | Customer attempted to access admin routes. | Redirect to storefront `/` with access denied banner. |
| **`403 Forbidden`** | `FORBIDDEN_ROLE_CREATION` | Store Admin tried to create a Super Admin. | Disable that role in the dropdown for Store Admin. |
| **`403 Forbidden`** | `FORBIDDEN_PERMISSION_DELEGATION` | Admin checked a permission they do not possess. | Show alert: "You cannot grant permissions you do not have." |
| **`404 Not Found`** | `USER_NOT_FOUND` | User ID does not exist in database. | Show 404 state in user detail drawer. |
| **`409 Conflict`** | `USER_ALREADY_EXISTS` | Email is already registered. | Show "Email already in use" under email input. |
| **`429 Too Many Requests`** | `RATE_LIMIT_EXCEEDED` | Over 300 requests in 15 mins (or 20 creation attempts). | Show alert: "Too many attempts. Please wait a few minutes." |
