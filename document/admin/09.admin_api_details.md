# Admin API Integration & CRUD Operations Specification

**Document Reference:** `document/admin/09.admin_api_details.md`  
**Target Audience:** Frontend Engineers (Admin Dashboard / Portal), Backend Developers, QA  
**Base URL:** `http://localhost:5000/api/v1` (or `/api/v1` in production)  
**Authentication:** Required for all routes (`Authorization: Bearer <jwt_access_token>`)  
**Status:** Implemented & Verified in Backend  

---

## 1. Executive Summary & Purpose

This specification outlines the newly added and updated **Admin API endpoints** to provide full CRUD coverage across the administration platform. Specifically:

1. **Customer CRM (Brand New Module):** Comprehensive customer management (`/api/v1/admin/customers`) including customer listing with lifetime value (LTV), single Customer 360 profile, customer creation, editing, and safe deletion/deactivation.
2. **Admin User & Staff Management (Completed CRUD):** Added `DELETE /api/v1/admin/users/:id` with strict role-hierarchy checks and self-deletion prevention.
3. **Inventory Management (Completed CRUD):** Added single inventory lookup `GET /api/v1/admin/inventory/:id` returning stock status, variant attributes, and recent audit movements.
4. **Order Management (Completed CRUD):** Added `DELETE /api/v1/admin/orders/:id` with automatic stock restoration for non-terminal orders.

## 3. Module 1: Customer CRM (`/api/v1/admin/customers`)

### 3.1 List Customers
* **Endpoint:** `GET /api/v1/admin/customers`
* **Query Parameters:**
  * `page` (number, default: `1`): Current page
  * `limit` (number, default: `20`, max: `100`): Items per page
  * `search` (string, optional): Matches customer `name`, `email`, or `phone` (case-insensitive)
  * `sortBy` (string, default: `createdAt`): One of `createdAt`, `totalSpent`, `orderCount`, `name`
  * `sortOrder` (string, default: `desc`): `asc` or `desc`
  * `isActive` (boolean string, optional): `true` or `false`

* **Endpoint:** `POST /api/v1/admin/customers`
* **Content-Type:** `application/json` OR `multipart/form-data` (if uploading avatar file)
* **Request Body:**
```json

  "name": "Victoria Beckham",
  "email": "victoria@example.com",
  "password": "SecurePassword123",
  "phone": "9876543299",
  "avatarUrl": "https://res.cloudinary.com/.../avatar.jpg",
  "address": {
    "firstName": "Victoria",
    "lastName": "Beckham",
    "company": "VB Studio",
    "address1": "12 Kensington Palace Gardens",
    "address2": "Suite 2",
    "city": "London",
    "state": "London",
    "postalCode": "W8 4QP",
    "country": "UK",

```

> * `password` is optional. If omitted, a cryptographically secure random password is auto-generated.

  "message": "Customer account created successfully",

### 3.5 Delete / Deactivate Customer
* **Endpoint:** `DELETE /api/v1/admin/customers/:id`
* **Path Parameter:** `id` (UUID): Customer user ID

#### Behavior:
* **Customer has 0 orders:** Hard-deletes the customer record completely (cascading wishlist, cart, and addresses).
* **Customer has 1+ orders:** Protects historical sales data by **soft-deactivating** the account (`isActive: false`) and invalidating all active refresh tokens.

#### Success Response (`200 OK`):
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Customer 'Lady Victoria Beckham' deleted successfully",
  "data": {
    "id": "4781b3d0-d3e3-4f5e-a441-a365eb9b596b",
    "name": "Lady Victoria Beckham",
    "email": "lady.victoria@example.com"
  }
}
```

## 4. Module 2: Staff & Admin User Deletion (`DELETE /api/v1/admin/users/:id`)

### 4.1 Delete Subordinate Admin / Staff
* **Endpoint:** `DELETE /api/v1/admin/users/:id`
* **Path Parameter:** `id` (UUID): User ID to delete
* **Access:** Private (`Admin` with hierarchy permission)

#### Strict Security Guards:
1. **Self-Deletion Forbidden:** An admin cannot delete their own account (`CANNOT_DELETE_SELF`).
2. **Hierarchy Enforcement:** An admin cannot delete an account of equal or higher rank (`FORBIDDEN_USER_DELETE`).
3. **Primary Super Admin Protection:** If deleting a `SUPER_ADMIN`, the system prevents deletion if it is the last active Super Admin (`CANNOT_DELETE_LAST_SUPER_ADMIN`).
4. **Creator Link Cleanup:** Before deletion, any staff accounts created by this user have their `createdById` safely unlinked to prevent foreign key errors.

#### Success Response (`200 OK`):
```json
{
  "success": true,
  "statusCode": 200,
  "message": "User 'John Staff' (STAFF) deleted successfully",
  "data": {
    "user": {
      "id": "f5e86aae-bc0d-4fc0-8631-a261958acd9e",
      "name": "John Staff",
      "email": "john.staff@teststore.com",
      "role": "STAFF"
    }
  }
}
```

## 5. Module 3: Inventory Single Item Lookup (`GET /api/v1/admin/inventory/:id`)

### 5.1 Get Inventory Record & Audit History
* **Endpoint:** `GET /api/v1/admin/inventory/:id`
* **Path Parameter:** `id` (UUID): `variantId` OR `productId`
* **Access:** Private (`inventory:read`)

#### Key Features:
* Automatically identifies whether the ID belongs to a garment **Variant** (with Size/Color attributes) or a standalone **Product**.
* Returns stock quantity, low-stock threshold, price breakdown, and the **10 most recent inventory audit transactions** (type, quantity change, previous/new stock, reason, staff actor).

## 6. Module 4: Order Deletion (`DELETE /api/v1/admin/orders/:id`)

### 6.1 Delete Order
* **Endpoint:** `DELETE /api/v1/admin/orders/:id`
* **Path Parameter:** `id` (UUID): Order ID
* **Access:** Private (`orders:cancel`)

#### Automatic Inventory Restoral:
* If the order is in an active state (`PENDING`, `CONFIRMED`, `PROCESSING`, `PACKED`, `SHIPPED`), deleting it will **automatically restore the reserved garment stock** back into warehouse inventory and log a `RETURN` transaction in the inventory ledger.
* If the order was already `CANCELLED` or `DELIVERED`, stock is untouched to prevent duplicate stock creation.
* Cascading deletes clean up associated line items, payment records, status history, and coupon usage tracking.

#### Success Response (`200 OK`):
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Order #ORD-20261018-9A72 deleted successfully",
  "data": {
    "id": "order-uuid-1",
    "orderNumber": "ORD-20261018-9A72",
    "status": "CANCELLED"
  }
}
```

## 7. Frontend Integration Guide & Component Checklist

### 1. Customers Screen (`/admin/customers`)
* **Table Columns:** Name & Avatar, Email, Phone, Location (City/State), Total Orders, Total Spent (LTV), Last Order Date, Status Badge (`Active`/`Inactive`), Actions (`View`, `Edit`, `Delete`).
* **Search & Filters:** Debounced search bar (triggers `?search=...`), sort dropdown (`sortBy=totalSpent&sortOrder=desc`), status filter (`?isActive=true`).
* **Customer 360 Drawer / Modal (`GET /customers/:id`):**
  * Top Header: Avatar, Name, Email, Phone, Account Age.
  * Stat Cards: Lifetime Value (₹), Total Orders, Completed Orders, Pending Orders, Average Order Value (₹).
  * Tabs:
    * **Orders Tab:** Quick table of recent orders with status badges and links to `/admin/orders/:id`.
    * **Addresses Tab:** Card list of saved addresses highlighting the Default Address.
* **Create Customer Modal (`POST /customers`):**
  * Inputs: Name, Email, Phone, Password (optional with "Auto-generate" toggle), Avatar upload or URL.
  * Collapsible Address Section: First/Last name, Street, City, State, Postal code.
* **Delete Confirmation Modal:**
  * Displays warning: *"If this customer has placed orders, the account will be deactivated instead of permanently deleted to preserve revenue history."*

### 2. Staff Management Screen (`/admin/users`)
* **Add "Delete Staff" action button:**
  * Disable the button if the user row matches the logged-in admin (`currentUser.id === row.id`) or if the staff member is a higher role.
  * On click, open confirmation modal: *"Are you sure you want to delete staff account {name}?"*
  * Call `DELETE /api/v1/admin/users/:id`.

### 3. Inventory Screen (`/admin/inventory`)
* **Row Click / "Inspect" Modal (`GET /inventory/:id`):**
  * Displays garment thumbnail, SKU, current stock vs. threshold progress bar.
  * Timeline table displaying the `recentTransactions` history showing who adjusted stock, quantity change (`+10` or `-3`), and the business reason.

### 4. Orders Screen (`/admin/orders`)
* **Order Actions Menu:**
  * Add **"Delete Order"** button (red danger option).
  * Prompt confirmation modal: *"Deleting this active order will restore reserved items back into warehouse stock."*
  * Call `DELETE /api/v1/admin/orders/:id`.

## 8. Error Codes & Handling Reference

| HTTP Status | Error Code | Trigger Condition | Recommended Frontend Display |
| :--- | :--- | :--- | :--- |
| `400 BAD_REQUEST` | `CANNOT_DELETE_SELF` | Admin attempts to call `DELETE /admin/users/:id` on their own ID | *"You cannot delete your own account."* |
| `400 BAD_REQUEST` | `CANNOT_DELETE_LAST_SUPER_ADMIN` | Attempting to delete the only active Super Admin | *"Cannot delete the primary/last active Super Admin account."* |
| `403 FORBIDDEN` | `FORBIDDEN_USER_DELETE` | Staff or Store Admin attempts to delete someone of equal or higher rank | *"You do not have permission to delete this user."* |
| `404 NOT_FOUND` | `CUSTOMER_NOT_FOUND` | Customer ID does not exist or user is not a customer | *"Customer record not found."* |
| `404 NOT_FOUND` | `ORDER_NOT_FOUND` | Order ID does not exist | *"Order not found."* |
| `404 NOT_FOUND` | `INVENTORY_NOT_FOUND` | ID does not match any variant or product | *"Inventory record not found."* |
| `409 CONFLICT` | `EMAIL_ALREADY_EXISTS` | Email entered is already registered to another account | Form error: *"An account with this email already exists."* |
| `400 BAD_REQUEST` | `IMAGE_INPUT_CONFLICT` | Frontend sends both a file upload and a URL string | *"Please choose either a file upload or an image URL."* |
