## 1. Architecture & Frontend Screen Mapping

The order system is designed for modern e-commerce storefronts and admin dashboards. All customer-facing URLs and API routes use the human-readable **`orderNumber`** (e.g. `ORD-20261012-7A3B`) instead of internal database UUIDs.

```
+---------------------------------------------------------------------------------------------------------------------------------+
|                                                   ORDER SYSTEM ARCHITECTURE                                                     |
+---------------------------------------------------------------------------------------------------------------------------------+
|                                                                                                                                 |
|   1. POST-CHECKOUT SUCCESS                  2. CUSTOMER ACCOUNT ORDERS                  3. CUSTOMER ORDER DETAILS               |
|   Route: /orders/:orderNumber/confirmation  Route: /orders                              Route: /orders/:orderNumber             |
|   +--------------------------------------+  +----------------------------------------+  +------------------------------------+  |
|   | Order Confirmation Screen            |  | Order History List Screen              |  | Order Details & Tracking Screen    |  |
|   | - Thank You & Order Summary          |  | - Paginated order cards                |  | - Complete garment snapshots       |  |
|   | - Payment & Fulfilment Status        |  | - Status badges (PENDING, SHIPPED,...) |  | - Delivery & courier tracking      |  |
|   | - Delivery Address Snapshot          |  | - Items summary & thumbnail preview    |  | - Fulfilment status timeline       |  |
|   | - Public Metafields (e.g. Gift Note) |  | - "View Details" & "Reorder" buttons   |  | - "Cancel Order" (if PENDING)      |  |
|   | - Link to Order Details / Home       |  | - Status filter tabs                   |  | - "Reorder / Buy Again" button     |  |
|   +--------------------------------------+  +----------------------------------------+  +------------------------------------+  |
|                      ^                                          ^                                          ^                    |
|                      |                                          |                                          |                    |
|                      +------------------------------------------+------------------------------------------+                    |
|                                                                 |                                                               |
|                                             BACKEND API LAYER (/api/v1/orders)                                                  |
|                                                                 |                                                               |
|                      +------------------------------------------+------------------------------------------+                    |
|                      |                                                                                     |                    |
|                      v                                                                                     v                    |
|   4. STORE OPERATIONS ADMIN                                                              5. STATE & INVENTORY ENGINES           |
|   Route: /admin/orders/*                                                                 - Atomic inventory reserve & return    |
|   - Order status transitions (PENDING -> CONFIRMED -> PROCESSING -> SHIPPED -> DELIVERED) - Dual status: Order vs Payment      |
|   - Courier tracking assignment (AWB, Courier Partner)                                   - Audit trail in OrderStatusHistory    |
|   - COD Payment Collection recording (PaymentStatus -> COMPLETED)                        - Public & Private OrderMetafields     |
|   - Metafield CRUD (public delivery notes, internal warehouse bin IDs)                                                          |
+---------------------------------------------------------------------------------------------------------------------------------+
```

### Key Business Rules for Frontend Developers:
1. **Order Identifier:** Customers always interact with **`orderNumber`** (e.g., `ORD-20261012-7A3B`). Never expose internal database UUIDs in customer URLs.
2. **Order Status vs. Payment Status Separation:**
   * **`status` (Fulfilment State):** `PENDING` $\rightarrow$ `CONFIRMED` $\rightarrow$ `PROCESSING` $\rightarrow$ `PACKED` $\rightarrow$ `SHIPPED` $\rightarrow$ `OUT_FOR_DELIVERY` $\rightarrow$ `DELIVERED` $\rightarrow$ `CANCELLED`.
   * **`paymentStatus` (Financial State):** `PENDING`, `COMPLETED`, `FAILED`, `REFUNDED`.
   * For **COD (Cash on Delivery)**, an order will be `status: "CONFIRMED"` or `"SHIPPED"`, while `paymentStatus` remains `"PENDING"` until the courier or store admin verifies that cash has been collected.
3. **Customer Self-Cancellation:** Customers are strictly permitted to cancel their order only while `status === "PENDING"`. Once an order advances to `CONFIRMED`, `PROCESSING`, or `SHIPPED`, the cancel button should be hidden or disabled with a message to contact customer concierge.
4. **Reorder Merging:** Reorder does **not** wipe the customer's existing cart. It adds eligible garments to their current active cart at current prices, gracefully reporting any out-of-stock items.

1. **Visual Stepper Timeline:** Use `statusHistory` and current `status`:
   * Step 1: **Ordered** (Done)
   * Step 2: **Confirmed** (Done)
   * Step 3: **Shipped** (Active)
   * Step 4: **Out for Delivery** (Pending)
   * Step 5: **Delivered** (Pending)
2. **Courier Tracking Card:** Only render if `courierPartner` and `trackingNumber` are not null:
   * Show courier badge: **Delhivery Express**
   * Tracking Number (AWB): **DLH7894561230** with a copy-to-clipboard button.
   * Estimated Delivery: Formatted date (e.g., *"Expected by Oct 16, 2026"*).
3. **Cancellation Button State:**
   * If `status === "PENDING"`, render a secondary button: `[Cancel Order]`.
   * Clicking opens a confirmation modal asking for an optional reason and calls `POST /api/v1/orders/:orderNumber/cancel`.
   * If `status !== "PENDING"`, do **not** render the cancel button.

### Action 1: Customer Self-Cancellation
* **API Endpoint:** `POST /api/v1/orders/:orderNumber/cancel`
* **Authentication:** Required (`Authorization: Bearer <customerAccessToken>`)
* **Eligibility Rule:** Only allowed when `order.status === "PENDING"`.

#### Request
```http
POST /api/v1/orders/ORD-20261012-7A3B/cancel HTTP/1.1
Host: localhost:5000
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

```json
{
  "reason": "Ordered wrong size by mistake"
}
```

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `reason` | `string` | No | Optional cancellation reason (max 500 characters) |

#### Success Response (`200 OK`)
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Order #ORD-20261012-7A3B successfully cancelled",
  "data": {
    "id": "c1f7a0b3-8b7a-4ecb-99d6-54a86b3e1a02",
```

#### Error Responses
| HTTP Status | Error Code | Description & Frontend Handling |
| :--- | :--- | :--- |
| `400 Bad Request` | `CANCELLATION_NOT_ALLOWED` | Order is no longer in `PENDING` status. Show toast: *"Your order has already been processed and cannot be cancelled directly. Please contact our support team."* |
| `400 Bad Request` | `ORDER_ALREADY_CANCELLED` | Order has already been cancelled. |
| `404 Not Found` | `ORDER_NOT_FOUND` | Order does not exist or does not belong to the user. |


| Field | Type | Required | Description |

### 3.2 Update Order Status (Fulfillment State Machine)
* **Endpoint:** `PATCH /api/v1/admin/orders/:id/status`
* **Permission:** `orders:write`

#### Valid Transition Matrix:
* `PENDING` $\rightarrow$ `CONFIRMED`, `CANCELLED`
* `CONFIRMED` $\rightarrow$ `PROCESSING`, `CANCELLED`
* `PROCESSING` $\rightarrow$ `PACKED`, `CANCELLED`
* `PACKED` $\rightarrow$ `SHIPPED`, `CANCELLED`
* `SHIPPED` $\rightarrow$ `OUT_FOR_DELIVERY`, `DELIVERED`, `RETURN_REQUESTED`
* `OUT_FOR_DELIVERY` $\rightarrow$ `DELIVERED`, `RETURN_REQUESTED`
* `DELIVERED` $\rightarrow$ `RETURN_REQUESTED`

#### Request
```http
PATCH /api/v1/admin/orders/c1f7a0b3-8b7a-4ecb-99d6-54a86b3e1a02/status HTTP/1.1
Host: localhost:5000
Content-Type: application/json
Authorization: Bearer <adminAccessToken>
```

```json
{
  "status": "CONFIRMED",
  "comment": "Garment inventory reserved and sent to tailoring"
}
```

* **Endpoint:** `PATCH /api/v1/admin/orders/:id/shipping`
* **Permission:** `orders:write`

### 3.4 Manage Order Metafields (Public vs. Private)
* **List Metafields:** `GET /api/v1/admin/orders/:id/metafields` (`orders:read`)
* **Create/Update Metafield:** `POST /api/v1/admin/orders/:id/metafields` (`orders:write`)
* **Delete Metafield:** `DELETE /api/v1/admin/orders/:id/metafields/:metafieldId` (`orders:write`)

#### Upsert Metafield Request:
```http
POST /api/v1/admin/orders/c1f7a0b3-8b7a-4ecb-99d6-54a86b3e1a02/metafields HTTP/1.1
Host: localhost:5000
Content-Type: application/json
Authorization: Bearer <adminAccessToken>
```

```json
{
  "namespace": "warehouse",
  "key": "bin_location",
  "value": "RACK-4-SHELF-B",
  "valueType": "STRING",
  "description": "Internal picker bin location",
  "isPublic": false

```

> **Security Note:** Metafields with `isPublic: false` are **never** returned by customer endpoints (`GET /api/v1/orders/:orderNumber`). Only admins can read and manage private operational metadata.

## 4. Frontend Integration Cheatsheet (Quick Reference)

```typescript
// Example: TypeScript Axios Client for Customer Order Flow

import axios from 'axios';

const api = axios.create({
  baseURL: 'http://localhost:5000/api/v1',
  headers: { 'Content-Type': 'application/json' },
});

// Attach JWT access token
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('accessToken');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// 1. Fetch Order Confirmation (Screen 1)
export const getOrderConfirmation = async (orderNumber: string) => {
  const res = await api.get(`/orders/${orderNumber}/confirmation`);
  return res.data.data;
};

// 2. Fetch Customer Order History (Screen 2)
export const getCustomerOrders = async (page = 1, limit = 10, status = 'ALL') => {
  const res = await api.get('/orders', { params: { page, limit, status } });
  return res.data; // contains data: Order[], pagination: { total, totalPages }
};

// 3. Fetch Single Order Details & Tracking (Screen 3)
export const getOrderDetails = async (orderNumber: string) => {
  const res = await api.get(`/orders/${orderNumber}`);
  return res.data.data;
};

// 4. Cancel Order (Action 1)
export const cancelOrder = async (orderNumber: string, reason?: string) => {
  const res = await api.post(`/orders/${orderNumber}/cancel`, { reason });
  return res.data;
};

// 5. Reorder Products into Cart (Action 2)
export const reorderOrder = async (orderNumber: string) => {
  const res = await api.post(`/orders/${orderNumber}/reorder`);
  return res.data; // contains addedItems, skippedItems, cart
};
```
