## 1. Social OAuth Login API

### Endpoint Specification
- **Method:** `POST`
- **Route:** `/auth/social-login`
- **Full URL:** `https://dress-ecomm-backend.onrender.com/api/v1/auth/social-login` (or `/api/auth/social-login`)
- **Access:** Public (Protected by rate limiter)

### How It Works Under the Hood
1. **Dual Ingestion Flow**:
   - **Flow A (Google OAuth Token)**: Frontend sends `{ provider: "google", token: "<google_id_token_or_access_token>" }`. The backend securely validates the token against Google's OAuth2 endpoints (`tokeninfo` or `userinfo`), extracts the verified `email`, `sub` (`providerAccountId`), `name`, and `picture` (`avatarUrl`).
   - **Flow B (Pre-verified / NextAuth / Firebase / Apple)**: Frontend passes `{ provider, providerAccountId, email, name, avatarUrl }`.
2. **Account Linking & Persistence**:
   - First checks if an `Account` record exists for `(provider, providerAccountId)`. If found, logs the user in.
   - If not found, checks if a user already exists with that `email`. If yes, it links the new social provider to the existing account.
   - If user does not exist, it creates a new `User` (with `role: CUSTOMER`, `passwordHash: null`) and creates the `Account` record atomically.
3. **Session & Security**:
   - Issues a JWT `accessToken` (valid for 15 minutes).
   - Generates a cryptographically secure `refreshToken` and sets it as an `HttpOnly`, `SameSite=None`, `Secure` cookie named `refreshToken`.
   - Also returns the user object identical to regular email/password login.

### Request Payload

```json
{
  "provider": "google",
  "token": "eyJhbGciOiJSUzI1NiIsImtpZCI6...",
  "providerAccountId": "1098234729384729384",
  "email": "customer@gmail.com",
  "name": "Priya Sharma",
  "avatarUrl": "https://lh3.googleusercontent.com/a/ACg8ocL..."
}
```

#### Field Rules:
| Field | Type | Required? | Description |
| :--- | :--- | :--- | :--- |
| `provider` | `string` | **Required** | One of: `"google"`, `"facebook"`, `"github"`, `"apple"`. |
| `token` | `string` | **Optional\*** | OAuth ID Token or Access Token received from the provider SDK. |
| `providerAccountId` | `string` | **Optional\*** | The unique user ID assigned by the provider (e.g. Google `sub`). Required if `token` is not supplied. |
| `email` | `string` | **Optional\*** | Valid customer email. Required if `token` is not supplied. |
| `name` | `string` | Optional | Customer's full display name. |
| `avatarUrl` | `string` | Optional | Profile photo URL provided by OAuth provider. |

*\*Note: Either `token` OR both `(providerAccountId, email)` must be provided.*

## 2. Verification of Core Authentication Flows

Both the credentials flow and token lifecycle have been verified with 100% test pass rates:

1. **Registration (`POST /auth/register`)**:
   - Strictly enforces `CUSTOMER` role (staff and admins can only be created via the Admin panel).
   - Hashes passwords with salt rounds via bcrypt.
   - Prevents duplicate email collisions (`409 Conflict`).
2. **Login (`POST /auth/login`)**:
   - Safe against timing and user enumeration attacks.
   - Authenticates credentials, generates JWT access token, and issues refresh token.
3. **Token Rotation & Refresh (`POST /auth/refresh`)**:
   - Automatically reads the `refreshToken` from either the secure HttpOnly cookie OR request body `{ "refreshToken": "..." }`.
   - **One-time Token Rotation**: When used, the old refresh token is immediately deleted and replaced with a new random refresh token to prevent replay attacks.
   - Reusing an old refresh token returns `401 Unauthorized` (`INVALID_REFRESH_TOKEN`).
4. **Logout (`POST /auth/logout`)**:
   - Deletes the refresh token from the database and clears the browser cookie.
5. **Profile (`GET /auth/me`)**:
   - Returns authenticated user details and permissions.

## 4. Frontend Integration Snippets

### A. React / Next.js Google Sign-In Integration

```javascript
import { useGoogleLogin } from '@react-oauth/google';

export function GoogleLoginButton() {
  const loginWithGoogle = useGoogleLogin({
    onSuccess: async (tokenResponse) => {
      // Send access_token or credential to backend
      const res = await fetch('https://dress-ecomm-backend.onrender.com/api/v1/auth/social-login', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        credentials: 'include', // Important to save HttpOnly refreshToken cookie!
        body: JSON.stringify({
          provider: 'google',
          token: tokenResponse.access_token,
        }),
      });

      const data = await res.json();
      if (data.success) {
        // Store accessToken in memory / Auth state
        localStorage.setItem('accessToken', data.data.accessToken);
        console.log('Logged in user:', data.data.user);
      }
    },
    onError: (error) => console.error('Google Sign In Failed', error),
  });

  return (
    <button onClick={() => loginWithGoogle()} className="google-btn">
      Sign in with Google
    </button>
  );
}
```

### B. Standard Paginated Fetch Pattern

```javascript
async function fetchStorefrontProducts(page = 1, limit = 20, filters = {}) {
  const params = new URLSearchParams({
    page: String(page),
    limit: String(limit),
    ...filters,
  });

  const res = await fetch(`https://dress-ecomm-backend.onrender.com/api/v1/products?${params}`);
  const result = await res.json();

  return {
    products: result.data,
    pagination: result.pagination, // { page, limit, total, totalPages, hasMore }
  };
}
```

## 5. Customer Profile Image / Avatar Upload (Normal & Social Users)

### Overview
Both **Google / Social users** and **Normal email/password users** can upload or set their profile picture.
- **Social / Google Users**: Their avatar is automatically extracted from Google (`picture` field) upon login and saved to their `User.avatarUrl`.
- **Normal Users**: Can upload an image file directly (which gets automatically processed and hosted via Cloudinary) **OR** provide an image URL.

### Available Avatar Upload Endpoints

| Scenario | HTTP Method | Endpoint | Supported Content Types | Parameters / Fields |
| :--- | :--- | :--- | :--- | :--- |
| **1. At Registration** | `POST` | `/auth/register` | `multipart/form-data` OR `application/json` | File field: `avatar` or `image`<br>URL field: `avatarUrl` |
| **2. Social Sign-In** | `POST` | `/auth/social-login` | `application/json` | Auto-extracted from Google or passed in `avatarUrl` |
| **3. Dedicated Avatar Upload** | `POST` | `/customer/account/avatar` | `multipart/form-data` OR `application/json` | File field: `avatar` or `image`<br>URL field: `avatarUrl` |
| **4. Account Profile Update** | `PATCH` / `PUT` | `/customer/account` | `multipart/form-data` OR `application/json` | File field: `avatar` or `image`<br>URL field: `avatarUrl` (along with `name`, `phone`) |

---

### Detailed Usage & Frontend Examples

#### Method A: Direct File Upload via Cloudinary (`multipart/form-data`)

When a user selects an image from their device (e.g. `<input type="file" />`):

```javascript
// 1. Upload during Registration
async function registerWithAvatarFile(file, name, email, password, phone) {
  const formData = new FormData();
  formData.append('name', name);
  formData.append('email', email);
  formData.append('password', password);
  if (phone) formData.append('phone', phone);
  if (file) formData.append('avatar', file); // Can use 'avatar' or 'image'

  const res = await fetch('https://dress-ecomm-backend.onrender.com/api/v1/auth/register', {
    method: 'POST',
    body: formData, // Browser automatically sets Content-Type to multipart/form-data with boundary
  });

  return await res.json();
}

// 2. Upload or Change Avatar for Logged-In Customer
async function updateCustomerAvatar(file, accessToken) {
  const formData = new FormData();
  formData.append('avatar', file); // Accepts jpeg, png, webp, heic up to 5MB

  const res = await fetch('https://dress-ecomm-backend.onrender.com/api/v1/customer/account/avatar', {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${accessToken}`,
    },
    body: formData,
  });

  return await res.json();
}
```

#### Method B: Providing an External Image URL (`application/json`)

If the frontend hosts images or allows users to paste an image URL (e.g. from Google Drive, Unsplash, or CDN):

```javascript
// 1. Register with Image URL
async function registerWithAvatarUrl(name, email, password, phone, avatarUrl) {
  const res = await fetch('https://dress-ecomm-backend.onrender.com/api/v1/auth/register', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      name,
      email,
      password,
      phone,
      avatarUrl, // e.g. "https://images.unsplash.com/photo-..."
    }),
  });

  return await res.json();
}

// 2. Update Avatar with Image URL for Logged-In Customer
async function updateAvatarWithUrl(avatarUrl, accessToken) {
  const res = await fetch('https://dress-ecomm-backend.onrender.com/api/v1/customer/account/avatar', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${accessToken}`,
    },
    body: JSON.stringify({
      avatarUrl,
    }),
  });

  return await res.json();
}
```

#### Safety & Conflict Prevention
- The backend features strict **mutual exclusivity validation**: if a client accidentally sends both a file upload AND an `avatarUrl` in the same request, it returns a clear `400 Bad Request` with `IMAGE_INPUT_CONFLICT` explaining to send one or the other.
