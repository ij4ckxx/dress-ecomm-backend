## 2. Wishlist API (`GET /wishlist`)

### Specification
- **Method:** `GET`
- **Path:** `/api/v1/wishlist` (or `/api/wishlist`, `/api/v1/customer/wishlist`)
- **Access:** Private (Authenticated Customer via `Bearer <accessToken>`)
- **Controller:** `src/controllers/client/wishlist.controller.js` -> `getWishlist`
- **Service:** `src/services/client/wishlist.service.js` -> `getCustomerWishlistService`
- **Validator:** `src/validators/client/wishlist.validator.js` -> `wishlistQuerySchema`

### Supported Query Parameters
| Parameter | Type | Required | Default | Allowed Values / Validation | Description |
| :--- | :--- | :---: | :--- | :--- | :--- |
| `page` | `integer` | No | `1` | `>= 1` | Current page number. |
| `limit` | `integer` | No | `10` | `1` to `50` | Number of wishlisted items per page. |
| `search` | `string` | No | None | Text string | Searches product name, brand, and SKU. |
| `sort` | `string` | No | `newest` | `newest`, `oldest`, `price_asc`, `price_desc`, `name_asc`, `name_desc` | Sort order of items in wishlist. |
| `inStock` | `string` | No | `all` | `all`, `true`, `false` | Filters products by inventory availability. |

## 4. Customer Addresses API (`GET /customer/addresses`) [NEWLY IMPLEMENTED]

### Why It Needed Pagination
Previously, `GET /api/v1/customer/addresses` ran an unpaginated query returning all user addresses without support for query parameters. To support customers with extensive address books, power buyers, gift registries, or business accounts, full pagination was implemented.

### Specification
- **Method:** `GET`
- **Path:** `/api/v1/customer/addresses` (or `/api/customer/addresses`)
- **Access:** Private (Authenticated Customer via `Bearer <accessToken>`)
- **Controller:** `src/controllers/client/address.controller.js` -> `getAddresses`
- **Service:** `src/services/client/address.service.js` -> `getAddressesService`
- **Validator:** `src/validators/address.validator.js` -> `addressQuerySchema`

### Supported Query Parameters
| Parameter | Type | Required | Default | Allowed Values / Validation | Description |
| :--- | :--- | :---: | :--- | :--- | :--- |
| `page` | `integer` | No | `1` | `>= 1` | Current page number. |
| `limit` | `integer` | No | `10` | `1` to `50` | Number of addresses per page. |
| `search` | `string` | No | None | Text string | Searches across `address1`, `address2`, `city`, `state`, `postalCode`, `country`, `company`, `firstName`, `lastName`, and `phoneNumber`. |
| `sort` | `string` | No | `newest` | `newest`, `oldest`, `city_asc`, `city_desc` | Sort ordering. The default address (`isDefault: true`) is **always pinned first**. |
| `all` | `boolean` | No | `false` | `true`, `false` | When `true`, returns all addresses in a single payload. Ideal for checkout address pickers while preserving pagination envelope. |

### Full Backwards Compatibility
The response format intentionally maintains **100% backwards compatibility** with the frontend:
1. `data.addresses` contains the array of addresses as expected by existing code like `json.data?.addresses`.
2. `data.pagination` and root `pagination` are both populated so any client extracting pagination from `json.pagination` or `json.data.pagination` will function seamlessly.
3. If no query parameters are passed (`GET /api/customer/addresses`), `page=1, limit=10` is applied automatically, or pass `?all=true` to retrieve all saved records.

## 5. Frontend Integration Snippets

### A. Fetching Paginated Customer Addresses
```typescript
interface PaginatedAddressesResponse {
  addresses: CustomerAddress[];
  pagination: {
    page: number;
    limit: number;
    total: number;
    totalPages: number;
    hasNextPage: boolean;
    hasPreviousPage: boolean;
  };
}

export async function fetchPaginatedAddresses(
  accessToken: string,
  page: number = 1,
  limit: number = 10,
  search?: string
): Promise<PaginatedAddressesResponse> {
  const params = new URLSearchParams({
    page: String(page),
    limit: String(limit),
  });

  if (search) params.append("search", search);

  const res = await fetch(`https://dress-ecomm-backend.onrender.com/api/v1/customer/addresses?${params}`, {
    method: "GET",
    headers: {
      Authorization: `Bearer ${accessToken}`,
    },
    cache: "no-store",
  });

  const json = await res.json();
  return {
    addresses: json.data?.addresses || [],
    pagination: json.pagination || {
      page,
      limit,
      total: json.data?.addresses?.length || 0,
      totalPages: 1,
      hasNextPage: false,
      hasPreviousPage: false,
    },
  };
}
```

### B. Fetching All Addresses for Checkout Dropdown (`all=true`)
```typescript
export async function fetchAllAddressesForCheckout(accessToken: string): Promise<CustomerAddress[]> {
  const res = await fetch(`https://dress-ecomm-backend.onrender.com/api/v1/customer/addresses?all=true`, {
    method: "GET",
    headers: {
      Authorization: `Bearer ${accessToken}`,
    },
    cache: "no-store",
  });

  const json = await res.json();
  return json.data?.addresses || [];
}
```
