# Folder Structure & Architecture Guide

A simple, beginner-friendly explanation of how this backend project is organized, what each folder does, and suggested additions like `constants` to keep things clean.

---

## 1. Quick Directory Overview

```text
dress-ecomm-backend/
├── prisma/               # Database schema & migrations (ORM)
├── src/
│   ├── config/           # App configuration (DB connection, env vars)
│   ├── constants/        # (Recommended) Static values, status codes, roles
│   ├── controllers/      # Handles incoming requests & sends responses
│   ├── middlewares/      # Interceptors (Auth check, error handler, rate limit)
│   ├── models/           # Custom data models / schemas (if needed beyond Prisma)
│   ├── routes/           # API endpoint URL definitions
│   ├── services/         # Core business logic & database queries
│   ├── utils/            # Helper functions (token generator, response formatters)
│   ├── validators/       # Input validation schemas (Joi / Zod / express-validator)
│   └── server.js         # App entry point (starts Express server)
├── .env                  # Private environment variables (secrets)
├── .env.example          # Template for environment variables
└── package.json          # Dependencies and npm scripts
```

---

## 2. What Goes Into Each Folder?

### `src/routes/`
- **What it is:** The entry point for API endpoints.
- **Functionality:** Maps an HTTP method (`GET`, `POST`, `PUT`, `DELETE`) and URL path to a controller.
- **Example:**
  - `routes/auth.routes.js`: Defines `/api/auth/register`, `/api/auth/login`.
  - `routes/product.routes.js`: Defines `/api/products`, `/api/products/:id`.

### `src/controllers/`
- **What it is:** The "manager" of the request.
- **Functionality:**
  - Extracts parameters, body, and query (`req.body`, `req.params`).
  - Calls the right service function.
  - Sends back the HTTP response (`res.status(200).json(...)`).
- **Rule of Thumb:** Keep controllers thin. Do **not** write raw business logic or heavy SQL here.

### `src/services/`
- **What it is:** The "brain" / business logic layer.
- **Functionality:**
  - Handles the real work (e.g., hash password, verify email, calculate cart total).
  - Interacts with Prisma to read or write database records.
- **Example:**
  - `services/auth.service.js`: `registerUser()`, `loginUser()`.
  - `services/product.service.js`: `getProductsByCategory()`.

### `src/middlewares/`
- **What it is:** Functions that run **between** the request hitting the route and reaching the controller.
- **Functionality:**
  - Authentication checks (verify JWT token).
  - Role-based permissions (Admin vs Customer).
  - Global error handling middleware.
- **Example:** `auth.middleware.js`, `error.middleware.js`.

### `src/validators/`
- **What it is:** Request data validation.
- **Functionality:**
  - Checks if the user provided required fields (e.g., valid email, password length >= 6).
  - Prevents bad/invalid data from ever reaching your controller.
- **Example:** `auth.validator.js`, `product.validator.js`.

### `src/config/`
- **What it is:** Central place for setup and configurations.
- **Functionality:**
  - Database connection instance (e.g., Prisma client export).
  - Environment variable loader.
  - Third-party configs (Cloudinary, Stripe, Nodemailer).
- **Example:** `db.js`, `env.js`.

### `src/utils/`
- **What it is:** Reusable helper functions across the whole app.
- **Functionality:**
  - Generic functions with no direct business logic.
  - Examples: Generating random tokens, formatting dates, standardized API response helper.
- **Example:** `apiResponse.js`, `jwt.js`.

### `prisma/`
- **What it is:** Database layer.
- **Functionality:**
  - `schema.prisma`: Defines database tables, columns, and relations.
  - `migrations/`: History of changes applied to the database.

## 3. Recommended Extra Folders (Keep It Simple)

You can easily expand the structure with these 2 simple folders:

### 1. `src/constants/` (Highly Recommended)
- **Why add it?** Avoid hardcoded strings (magic numbers/strings) across your files.
- **What to put inside:**
  - `roles.js`: `export const ROLES = { ADMIN: 'ADMIN', CUSTOMER: 'CUSTOMER' };`
  - `orderStatus.js`: `export const ORDER_STATUS = { PENDING: 'PENDING', SHIPPED: 'SHIPPED', DELIVERED: 'DELIVERED' };`
  - `httpStatusCodes.js`: Common status code mappings.

### 2. `src/types/` (Optional - if using JSDoc or TypeScript later)
- Common shared types or interfaces.

## 4. How a Request Flows (The Life of a Request)

```text
Client Request
      │
      ▼
1. routes/         ──► Matches URL path (e.g., POST /api/auth/register)
      │
      ▼
2. middlewares/    ──► Checks validation / auth token
      │
      ▼
3. controllers/    ──► Grabs data from req.body and calls service
      │
      ▼
4. services/       ──► Executes business logic & calls Prisma (Database)
      │
      ▼
5. controllers/    ──► Receives result and sends JSON response back to Client
```
