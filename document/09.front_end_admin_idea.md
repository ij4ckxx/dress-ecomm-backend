# Admin Backend Analysis & API Blueprint

> **Target:** Node.js Backend Development Team  
> **Frontend Consumer:** Next.js Luxury E-Commerce Platform (`/admin/*`)  
> **API Base:** `/api/v1`  
> **Target Base URL:** `https://dress-ecomm-backend.onrender.com/api/v1` (or local `http://localhost:5000/api/v1`)

---

## 1. Executive Summary & Architecture Overview

The frontend e-commerce platform is decoupled from internal Next.js backend routes. All server logic, database interactions, payment webhooks, and administrative operations are handled by a standalone **Node.js** server.

The **Admin Console** (`/admin`) serves store managers, staff, and super administrators to manage the complete fashion e-commerce lifecycle:
- Real-time business KPIs, revenue metrics, and inventory alerts
- Multi-variant apparel catalog management (sizes, color swatches, attributes)
- Variant-level inventory tracking with an auditable transaction ledger
- Category hierarchies, curated seasonal collections, and flash sale campaigns
- Order lifecycle state machine, packing workflows, and courier tracking
- Promotional coupon validation engine with usage quotas
- Real-time feature flags engine and multi-theme branding presets

## 2. Admin Security & Role-Based Access Control (RBAC)

The frontend verifies the admin session via `useAuthStore` using the user's role from the JWT payload or `/auth/me` endpoint.

### Role Hierarchy

| Role | Permissions | Admin Console Access |
| :--- | :--- | :---: |
| `SUPER_ADMIN` | Full root access across stores, settings, user roles, financial data, and configurations. | Yes |
| `STORE_ADMIN` | Full control over store catalog, orders, inventory, discounts, promotions, and settings. | Yes |
| `STAFF` | Can view and update orders, update inventory stock, and view catalog. Cannot modify settings or delete products. | Yes (Restricted) |
| `CUSTOMER` | Public storefront access only. Attempting to access `/admin` redirects to `/` with an "Access Restricted" alert. | No |

### Backend Guard Middleware

Every admin route must be protected by authentication and role validation middleware:

```typescript
export const requireAdmin = (req: Request, res: Response, next: NextFunction) => {
  const user = req.user; // populated by authenticateToken middleware
  if (!user) {
    return res.status(401).json({ success: false, message: "Unauthorized. Authentication required." });
  }
  const allowedRoles = ["SUPER_ADMIN", "STORE_ADMIN", "STAFF"];
  if (!allowedRoles.includes(user.role)) {
    return res.status(403).json({ success: false, message: "Forbidden. Admin privileges required." });
  }
  next();
};
```

## 3. Backend Gap Analysis: Existing vs. Required

| Domain | What Backend Currently Has | What is Missing & Needed for Admin | Priority |
| :--- | :--- | :--- | :---: |
| **Auth & RBAC** | Basic `/auth/register`, `/auth/login`, `/auth/me` | Role authorization middleware, Staff management, Role update endpoints | **High** |
| **Dashboard Metrics** | None (frontend displays mock telemetry) | `/admin/analytics/overview`, `/admin/analytics/inventory-alerts`, `/admin/analytics/recent-orders` | **High** |
| **Products & Variants** | Read-only public `/products` & `/products/:slug` | Admin CRUD (`POST`, `PUT`, `DELETE`), variant pricing, color hex swatches, image re-ordering | **Critical** |
| **Inventory Ledger** | Static `stockQuantity` field on variant | Dedicated transaction ledger (`RESTOCK`, `SALE`, `ADJUSTMENT`, `RETURN`), safety threshold alerts | **Critical** |
| **Order Lifecycle** | None or basic mock creation | Admin order list with multi-filter, detail view, status state transitions, courier tracking integration | **Critical** |
| **Category Tree** | Public `/categories` listing | Admin category CRUD, nested subcategories, slug collision handling, display order sorting | **Medium** |
| **Collections** | Static fallback lookbooks | Admin collections CRUD, linking/unlinking products to seasonal capsule edits | **Medium** |
| **Discounts & Coupons** | Local coupon checks (`LUXE10`, `WELCOME1000`) | DB-backed coupon rules, usage limits, expiration dates, per-user limits, usage count tracking | **High** |
| **Flash Promotions** | Hardcoded promo campaign in frontend config | Campaign CRUD, active banner schedule (`startDate`, `endDate`), discount links | **Low** |
| **Settings & Flags** | Runtime in-memory flags & theme selector | Persisted `StoreSettings`, `FeatureSettings`, `ThemeSettings` JSON models in database | **Medium** |

## 5. Recommended Database Schema (Prisma / PostgreSQL)

Below is the complete database schema design for the Node.js backend:

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

enum Role {
  SUPER_ADMIN
  STORE_ADMIN
  STAFF
  CUSTOMER
}

enum ProductStatus {
  DRAFT
  ACTIVE
  ARCHIVED
}

enum Gender {
  MEN
  WOMEN
  UNISEX
  KIDS
}

enum OrderStatus {
  PENDING
  CONFIRMED
  PROCESSING
  PACKED
  SHIPPED
  OUT_FOR_DELIVERY
  DELIVERED
  CANCELLED
  RETURN_REQUESTED
  RETURNED
  REFUNDED
}

enum PaymentStatus {
  PENDING
  COMPLETED
  FAILED
  REFUNDED
}

enum PaymentGatewayType {
  RAZORPAY
  STRIPE
  COD
}

enum DiscountType {
  PERCENTAGE
  FIXED
}

enum InventoryTransactionType {
  RESTOCK
  SALE
  ADJUSTMENT
  RETURN
}

model User {
  id           String        @id @default(cuid())
  email        String        @unique
  passwordHash String
  name         String
  phone        String?
  role         Role          @default(CUSTOMER)
  createdAt    DateTime      @default(now())
  updatedAt    DateTime      @updatedAt
  orders       Order[]
  couponUsages CouponUsage[]
  auditLogs    AuditLog[]

  @@index([email])
  @@index([role])
}

model Category {
  id            String        @id @default(cuid())
  name          String
  slug          String        @unique
  tagline       String?
  description   String?
  image         String?
  isFeatured    Boolean       @default(false)
  displayOrder  Int           @default(0)
  isActive      Boolean       @default(true)
  createdAt     DateTime      @default(now())
  subcategories Subcategory[]
  products      Product[]

  @@index([slug])
}

model Subcategory {
  id         String    @id @default(cuid())
  name       String
  slug       String    @unique
  categoryId String
  category   Category  @relation(fields: [categoryId], references: [id], onDelete: Cascade)
  createdAt  DateTime  @default(now())
  products   Product[]

  @@index([categoryId])
}

model Product {
  id               String              @id @default(cuid())
  name             String
  slug             String              @unique
  description      String              @db.Text
  shortDescription String?
  price            Float
  compareAtPrice   Float?
  costPrice        Float?
  sku              String?
  brand            String              @default("Maison De Élégance")
  gender           Gender              @default(WOMEN)
  status           ProductStatus       @default(ACTIVE)
  isFeatured       Boolean             @default(false)
  isNewArrival     Boolean             @default(false)
  isBestSeller     Boolean             @default(false)
  categoryId       String
  category         Category            @relation(fields: [categoryId], references: [id])
  subcategoryId    String?
  subcategory      Subcategory?        @relation(fields: [subcategoryId], references: [id])
  tags             String[]            @default([])
  fabricInfo       String?
  careInstructions String?
  sizeChartUrl     String?
  createdAt        DateTime            @default(now())
  updatedAt        DateTime            @updatedAt
  images           ProductImage[]
  variants         ProductVariant[]
  orderItems       OrderItem[]
  collections      ProductCollection[]

  @@index([slug])
  @@index([categoryId])
  @@index([status])
}

model ProductImage {
  id           String  @id @default(cuid())
  productId    String
  product      Product @relation(fields: [productId], references: [id], onDelete: Cascade)
  url          String
  altText      String?
  displayOrder Int     @default(0)
  isPrimary    Boolean @default(false)

  @@index([productId])
}

model ProductVariant {
  id                String                 @id @default(cuid())
  productId         String
  product           Product                @relation(fields: [productId], references: [id], onDelete: Cascade)
  sku               String                 @unique
  barcode           String?
  price             Float
  compareAtPrice    Float?
  stock             Int                    @default(0)
  reservedStock     Int                    @default(0)
  lowStockThreshold Int                    @default(5)
  size              String                 // "XS", "S", "M", "L", "XL", "38R"
  colorName         String                 // "Emerald Green"
  colorHex          String                 // "#046307"
  imageUrl          String?
  isActive          Boolean                @default(true)
  createdAt         DateTime               @default(now())
  updatedAt         DateTime               @updatedAt
  orderItems        OrderItem[]
  inventoryLogs     InventoryTransaction[]

  @@index([productId])
  @@index([sku])
}

model InventoryTransaction {
  id             String                   @id @default(cuid())
  variantId      String
  variant        ProductVariant           @relation(fields: [variantId], references: [id], onDelete: Cascade)
  type           InventoryTransactionType
  quantityChange Int                      // Positive for restock, negative for sale
  previousStock  Int
  newStock       Int
  reason         String?
  referenceId    String?                  // Order number, PO number, or Return ID
  createdAt      DateTime                 @default(now())

  @@index([variantId])
  @@index([createdAt])
}

model Collection {
  id          String              @id @default(cuid())
  name        String
  slug        String              @unique
  description String?             @db.Text
  image       String?
  isFeatured  Boolean             @default(false)
  createdAt   DateTime            @default(now())
  products    ProductCollection[]
}

model ProductCollection {
  productId    String
  product      Product    @relation(fields: [productId], references: [id], onDelete: Cascade)
  collectionId String
  collection   Collection @relation(fields: [collectionId], references: [id], onDelete: Cascade)

  @@id([productId, collectionId])
}

model Order {
  id                  String             @id @default(cuid())
  orderNumber         String             @unique
  userId              String?
  user                User?              @relation(fields: [userId], references: [id])
  guestName           String?
  guestEmail          String?
  guestPhone          String?
  subtotal            Float
```

## 6. Order State Machine & Fulfillment Rules

```
[PENDING]
   │ (Payment captured or COD verified)
   ▼
[CONFIRMED]
   │ (Admin assigns to atelier / warehouse)
   ▼
[PROCESSING]
   │ (Garment finished, steam-pressed, boxed)
   ▼
[PACKED]
   │ (Courier pickup & Waybill / AWB generated)
   ▼
[SHIPPED]
   │ (Courier out with delivery rider)
   ▼
[OUT_FOR_DELIVERY]
   │ (Customer receipt & OTP confirmation)
   ▼
[DELIVERED]
```

### Transition Validation Rules

| Current Status | Allowed Next Status | Triggering Action / Effect |
| :--- | :--- | :--- |
| `PENDING` | `CONFIRMED`, `CANCELLED` | On `CONFIRMED`: Move from available `stock` to `reservedStock`. On `CANCELLED`: Release stock. |
| `CONFIRMED` | `PROCESSING`, `CANCELLED` | Move order to warehouse packing queue. |
| `PROCESSING` | `PACKED`, `CANCELLED` | Quality inspection passed. Package sealed. |
| `PACKED` | `SHIPPED` | Requires `trackingNumber` & `courierPartner`. Transition locks items against edits. |
| `SHIPPED` | `OUT_FOR_DELIVERY`, `DELIVERED`, `RETURNED` | Courier webhook or manual delivery tracking update. |
| `DELIVERED` | `RETURN_REQUESTED` | Customer initiates return within return window (e.g. 7 days). |
| `CANCELLED` | *Terminal State* | Restore inventory via an `ADJUSTMENT` / `RETURN` transaction. Process gateway refund if prepaid. |
