# Authentication API Documentation (For Frontend Team)

**Base URL**:  
- **Localhost**: `http://localhost:5000/api/v1` *(or `/api`)*  
- **Production (Render)**: `https://dress-ecomm-backend.onrender.com/api/v1` *(or `/api`)*  

**Headers**: `Content-Type: application/json`  
**CORS Credentials**: Enabled (`credentials: 'include'` for cookies)

---

## 1. Quick Summary of Endpoints

| Method | Endpoint | Description | Auth Required |
| :--- | :--- | :--- | :--- |
| `GET` | `/health` | Server Health Status | No |
| `POST` | `/auth/register` | Register Customer, Staff, or Store Admin | No |
| `POST` | `/auth/login` | Authenticate user, returns JWT & HttpOnly cookie | No |
| `POST` | `/auth/logout` | Revoke session & clear refresh cookie | No (Idempotent) |
| `GET` | `/auth/me` | Get currently logged-in user profile | **Yes** (`Bearer <token>`) |

---

## 2. User Roles

Supported `role` values:
- `CUSTOMER` *(Default role for normal shoppers)*
- `STORE_ADMIN` *(For store managers / merchant admin panel)*
- `STAFF` *(For support & operations staff)*
- `SUPER_ADMIN` *(System owner with full global access)*

---

## 3. Social Login Ready (Google, Facebook, GitHub)

The backend schema and architecture are fully structured for Social / OAuth logins:
- **`passwordHash` is optional (`String?`)**: Users signing in via Google/Facebook do not have or require passwords.
- **Dedicated `Account` table**: Maps the provider (`google`, `facebook`, `github`) and provider user ID (`providerAccountId`) to the core user record.

### How the Frontend & Backend Will Handle Social Login:

```text
[Frontend (React / Next.js)]
       │
       ▼ 1. User clicks "Sign in with Google / GitHub"
   Google / GitHub SDK returns OAuth Credential / Access Token
       │
       ▼ 2. Frontend sends token to Backend:
   POST /api/v1/auth/social-login
       │
       ▼ 3. Backend verifies token with Provider, finds or creates User & Account
       │
       ▼ 4. Returns same JWT Access Token & HttpOnly Refresh Cookie
```

#### Social Login Endpoint (Design Specification)

- **Method**: `POST`
- **URL**: `/auth/social-login`
- **Auth**: None

##### Request Body
```json
{
  "provider": "google", // "google" | "facebook" | "github"
  "token": "oauth_token_or_id_token_received_from_provider",
  "role": "CUSTOMER" // Optional (defaults to CUSTOMER)
}
```

##### Success Response (`200 OK`)
> Returns standard authentication response identical to normal login:
```json
{
  "success": true,
  "message": "Login successful",
  "data": {
    "user": {
      "id": "d52f6280-185a-4890-bee1-e3a29886b42d",
      "name": "Jegannathan",
      "email": "user@gmail.com",
      "avatarUrl": "https://lh3.googleusercontent.com/a/...",
      "role": "CUSTOMER"
    },
    "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```
*(Also sets the standard `refreshToken` HttpOnly cookie, so all existing token refresh and logout logic work seamlessly!)*

## 4. Endpoints in Detail

### 1) Health Check
Check if the server is live.

- **Method**: `GET`
- **URL**: `/health` (e.g. `http://localhost:5000/api/v1/health`)
- **Success Response (`200 OK`)**:
```json
{
  "status": "ok",
  "message": "E-commerce API is running"
}
```

---

### 2) Register User
Creates a new customer or admin account.

- **Method**: `POST`
- **URL**: `/auth/register`
- **Auth**: None

#### Request Body
```json
{
  "name": "Jegannathan",
  "email": "user@example.com",
  "password": "Password123!",
  "phone": "+919876543210",
  "role": "CUSTOMER"
}
```

#### Fields & Rules
| Field | Type | Required? | Rules |
| :--- | :--- | :--- | :--- |
| `name` | `string` | **Yes** | 2 to 100 characters |
| `email` | `string` | **Yes** | Valid email (case-insensitive) |
| `password` | `string` | **Yes** | Min 8 chars, at least 1 letter and 1 number |
| `phone` | `string` | No | Optional phone number |
| `role` | `string` | No | Default: `"CUSTOMER"`. Allowed: `"CUSTOMER"`, `"STORE_ADMIN"`, `"STAFF"`, `"SUPER_ADMIN"` |

#### Success Response (`201 Created`)
```json
{
  "success": true,
  "message": "Registration successful",
  "data": {
    "user": {
      "id": "d52f6280-185a-4890-bee1-e3a29886b42d",
      "name": "Jegannathan",
      "email": "user@example.com",
      "role": "CUSTOMER",
      "phone": "+919876543210",
      "createdAt": "2026-09-30T15:55:52.286Z"
    }
  }
}
```

#### Error Responses
- **`400 Bad Request`** (Validation Failed):
  ```json
  {
    "success": false,
    "message": "Password must be at least 8 characters long",
    "error": {
      "code": "VALIDATION_ERROR",
      "details": [{ "field": "password", "message": "Password must be at least 8 characters long" }]
    }
  }
  ```
- **`409 Conflict`** (Email already exists):
  ```json
  {
    "success": false,
    "message": "An account with this email already exists"
  }
  ```

---

### 3) Login
Authenticates the user and returns an Access Token in JSON, and sets the Refresh Token as a secure `HttpOnly` cookie.

- **Method**: `POST`
- **URL**: `/auth/login`
- **Auth**: None

#### Request Body
```json
{
  "email": "user@example.com",
  "password": "Password123!"
}
```

#### Success Response (`200 OK`)
> **Note**: Sets an `HttpOnly` cookie named `refreshToken` (valid 7 days).
```json
{
  "success": true,
  "message": "Login successful",
  "data": {
    "user": {
      "id": "d52f6280-185a-4890-bee1-e3a29886b42d",
      "name": "Jegannathan",
      "email": "user@example.com",
      "role": "CUSTOMER"
    },
    "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```

#### Error Response (`401 Unauthorized`)
```json
{
  "success": false,
  "message": "Invalid email or password"
}
```

---

### 4) Logout
Invalidates the active refresh token session in the database and clears the `refreshToken` cookie.

- **Method**: `POST`
- **URL**: `/auth/logout`
- **Auth**: None (Optional: sends cookie automatically if credentials enabled)

#### Success Response (`200 OK`)
```json
{
  "success": true,
  "message": "Logout successful"
}
```

---

### 5) Get Current Profile (`/me`)
Used on frontend page load / route change to verify login and get user data.

- **Method**: `GET`
- **URL**: `/auth/me`
- **Headers**:
  ```http
  Authorization: Bearer <accessToken>
  ```
- **Auth**: Required (`Bearer <accessToken>`)

#### Success Response (`200 OK`)
```json
{
  "success": true,
  "message": "Profile fetched successfully",
  "data": {
    "user": {
      "id": "d52f6280-185a-4890-bee1-e3a29886b42d",
      "email": "user@example.com",
      "name": "Jegannathan",
      "role": "CUSTOMER",
      "isActive": true
    }
  }
}
```

#### Error Response (`401 Unauthorized`)
```json
{
  "success": false,
  "message": "Authentication required. Please log in to proceed."
}
```

## 5. Postman Environment Setup

Create an environment in Postman with:
- **Variable**: `base_url`
  - Local value: `http://localhost:5000/api/v1`
  - Production value: `https://dress-ecomm-backend.onrender.com/api/v1`

Then simply call:
- `GET {{base_url}}/health`
- `POST {{base_url}}/auth/register`
- `POST {{base_url}}/auth/login`
- `POST {{base_url}}/auth/logout`
- `GET {{base_url}}/auth/me` *(with Header: `Authorization: Bearer {{accessToken}}`)*
