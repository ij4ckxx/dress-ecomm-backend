## 1. Architecture & Tracking Pipeline Overview

The **Order Tracking & Timeline Engine** provides real-time, interactive order tracking for luxury dresses and garments. It is built directly into our backend so customers never have to leave the website or navigate to third-party courier portals.

```
+----------------------------------------------------------------------------------------------------------------------------------+
|                                                   ORDER TRACKING ARCHITECTURE                                                    |
+----------------------------------------------------------------------------------------------------------------------------------+
|                                                                                                                                  |
|   1. GUEST / PUBLIC TRACKING PAGE                 2. CUSTOMER ACCOUNT ORDERS PAGE                3. ADMIN OPERATIONS PANEL       |
|   Route: /track-order                             Route: /account/orders/:orderNumber            Route: /admin/orders/:id        |
|   - Form: Order Number + Email or Phone           - Zero-friction instant tracking               - Full customer & order details |
|   - No login required                             - Full address & payment details               - Advance fulfillment status    |
|   - Privacy masking on personal data              - Visual 5-step progress bar                   - Assign courier & AWB tracking |
|   - Visual 5-step progress bar                    - Interactive checkpoint timeline              - Add custom progress updates   |
|                                                                                                                                  |
|                                         +-----------------------------------------+                                              |
|                                         |    BACKEND SERVICE LAYER (/api/v1)      |                                              |
|                                         +-----------------------------------------+                                              |
|                                                              |                                                           |
|                            +---------------------------------+---------------------------------+                                 |
|                            |                                                                   |                                 |
|                            v                                                                   v                                 |
|             4. DUAL-MODE SECURITY GUARD                                         5. 5-STEP TIMELINE COMPILER                      |
|             - Authenticated: Validates req.user.id                              - Compiles currentStep (1 to 5)                  |
|             - Guest: Strict case-insensitive email match                        - Evaluates isCompleted & isCurrent              |
|               OR 10-digit phone suffix match                                    - Merges status transitions + checkpoints        |
|             - Masked PII: "P***a S***a", "p***5@example.com"                    - Exposes estimatedDelivery, courier, & AWB      |
+----------------------------------------------------------------------------------------------------------------------------------+
```

## 2. Canonical 5-Step Order Progression

The backend translates internal fulfillment states (`PENDING`, `CONFIRMED`, `PROCESSING`, `PACKED`, `SHIPPED`, `OUT_FOR_DELIVERY`, `DELIVERED`, `CANCELLED`, `RETURN_REQUESTED`, `RETURNED`, `REFUNDED`) into a standardized **5-step visual progress bar**:

| Step | Key | Step Title | Description | Active Backend Statuses |
| :---: | :--- | :--- | :--- | :--- |
| **1** | `ORDER_PLACED` | **Order Placed** | Order placed by customer and logged into system. | `PENDING` |
| **2** | `ORDER_CONFIRMED` | **Order Confirmed** | Order verified and sent to atelier for tailoring, finishing, and packaging. | `CONFIRMED`, `PROCESSING`, `PACKED` |
| **3** | `SHIPPED` | **Dispatched & In Transit** | Package dispatched with courier partner (displays courier partner name & AWB number). | `SHIPPED` |
| **4** | `OUT_FOR_DELIVERY`| **Out for Delivery** | Package arrived at local destination hub and courier agent is out for final delivery. | `OUT_FOR_DELIVERY` |
| **5** | `DELIVERED` | **Delivered** | Package successfully delivered to customer. | `DELIVERED` |

### Special States:
* **`isCancelled: true`** (`status: 'CANCELLED'`): Shows order cancellation banner with the recorded `cancelReason` and `cancelledAt` timestamp. `currentStep` is set to `0`.
* **`isReturn: true`** (`status: 'RETURN_REQUESTED'`, `'RETURNED'`, or `'REFUNDED'`): Highlights active return/refund progression.

## 3. Storefront (Client) Endpoints Reference

### 3.1 Public & Authenticated Order Tracking (Query & Direct URL)
* **Endpoints:**
  - `GET https://dress-ecomm-backend.onrender.com/api/v1/orders/track` (Query Parameters)
  - `GET https://dress-ecomm-backend.onrender.com/api/v1/orders/:orderNumber/track` (Path Parameter)
* **Authentication:** **Optional** (`optionalAuthenticate`).
  - **Logged-in Customer:** If the customer is logged in, passing `Authorization: Bearer <token>` automatically verifies ownership. **No email or phone query parameter is needed!**
  - **Guest / Unauthenticated Customer:** Provide either `email`, `phone`, or `emailOrPhone` to verify access.
* **Frontend Screen:** `/track-order` landing page, header "Track Order" link, or post-order link.

#### Query Parameters:
| Parameter | Type | Required for Guest? | Description |
| :--- | :--- | :--- | :--- |
| `orderNumber` | String | **Yes** (if using `/orders/track`) | Order number (e.g. `ORD-20261020-DX40`). In `/:orderNumber/track`, passed via URL path. |
| `email` | String | Optional | Customer email address associated with the order. |
| `phone` | String | Optional | Customer phone number associated with the order (matches last 10 digits). |
| `emailOrPhone`| String | Optional | Combined field matching either email or phone. |

#### Example 1 — Public Guest Tracking via URL:
```bash
curl -X GET "https://dress-ecomm-backend.onrender.com/api/v1/orders/ORD-20261020-DX40/track?email=priya@example.com" \
  -H "Accept: application/json"
```

#### Example 2 — Logged-in Customer Tracking (Zero Parameters):
```bash
curl -X GET "https://dress-ecomm-backend.onrender.com/api/v1/orders/ORD-20261020-DX40/track" \
  -H "Authorization: Bearer <CUSTOMER_ACCESS_TOKEN>" \
  -H "Accept: application/json"
```

### 3.3 Enhanced Order Details Endpoint (`GET /orders/:orderNumber`)
* **Endpoint:** `GET https://dress-ecomm-backend.onrender.com/api/v1/orders/:orderNumber`
* **Authentication:** Required (`Authorization: Bearer <customerAccessToken>`)
* **Enhancement Notice:** **No breaking changes!** The existing endpoint returns all original order details, line items, pricing, and metafields, but now **additionally includes the exact same `tracking` timeline object** so the customer order detail screen can render the 5-step progress bar out-of-the-box without making extra API calls.

## 4. Admin Panel APIs Reference (`/api/v1/admin/orders`)

All admin order endpoints require:
1. `Authorization: Bearer <adminAccessToken>`
2. Admin role (`SUPER_ADMIN`, `STORE_ADMIN`, or `STAFF`)
3. Granular permissions: `orders:read`, `orders:write`, or `orders:cancel`.

---

### 4.1 Get Full Order Detail with Live Tracking
* **Endpoint:** `GET https://dress-ecomm-backend.onrender.com/api/v1/admin/orders/:id`
* **Permission:** `orders:read`
* **Description:** Returns the entire order record along with customer profile, items, stock counts, payments, history, and the enriched `tracking` progress object.

---

### 4.2 Assign Shipping / Courier Credentials & Dispatch Order
* **Endpoint:** `PATCH https://dress-ecomm-backend.onrender.com/api/v1/admin/orders/:id/shipping`
* **Permission:** `orders:write`
* **Description:** Assigns courier partner, tracking number (AWB), and estimated delivery. Automatically advances status to `SHIPPED` (or selected status) and updates customer timeline.

#### Request Body:
```json
{
  "courierPartner": "Delhivery Express",
  "trackingNumber": "DL1234567890",
  "estimatedDelivery": "2026-10-28T18:00:00.000Z",
  "status": "SHIPPED",
  "notes": "Fragile luxury garment in velvet presentation box."
}
```

#### Success Response (`200 OK`):
```json
{
  "success": true,
  "message": "Shipping details updated and order dispatched successfully",
  "data": {
    "order": {
      "id": "52b1dffe-c1e7-4f13-8986-56afe3fac657",
      "orderNumber": "ORD-20261020-DX40",
```

### 4.3 Add Custom Tracking Checkpoint / Progress Update (NEW)
* **Endpoint:** `POST https://dress-ecomm-backend.onrender.com/api/v1/admin/orders/:id/checkpoints`
* **Permission:** `orders:write`
* **Description:** Allows warehouse, atelier, or support staff to add real-time progress updates or milestones that immediately display on the customer's timeline (e.g. tailoring progress, quality inspection, sorting facility milestone, or weather delays).

#### Request Body:
| Field | Type | Required? | Description |
| :--- | :--- | :--- | :--- |
| `comment` | String | **Required** | The checkpoint description (min 2, max 500 chars). |
| `location` | String | Optional | Facility or location tag (e.g. `"Central Atelier"`, `"Delhi Sorting Hub"`). Automatically formatted as `"[Location] Comment"`. |
| `status` | String | Optional | Optionally advance order status simultaneously (e.g. `"PROCESSING"`, `"PACKED"`, `"OUT_FOR_DELIVERY"`). |

#### Example Request:
```bash
curl -X POST "https://dress-ecomm-backend.onrender.com/api/v1/admin/orders/52b1dffe-c1e7-4f13-8986-56afe3fac657/checkpoints" \
  -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "comment": "Handcrafted embroidery inspection passed. Steaming and packaging underway.",
    "location": "Atelier Quality Lab",
    "status": "PACKED"
  }'
```

#### Success Response (`201 Created`):

## 5. Frontend UI/UX Component Implementation Guide

### 1. Rendering the 5-Step Progress Bar
```jsx
// React / Next.js Component Example
const OrderProgressBar = ({ tracking }) => {
  return (
    <div className="flex items-center justify-between w-full py-6">
      {tracking.steps.map((step, idx) => (
        <div key={step.step} className="flex flex-col items-center flex-1 relative">
          {/* Connector Line */}
          {idx > 0 && (
            <div
              className={`absolute top-4 -left-1/2 w-full h-1 ${
                step.isCompleted ? 'bg-emerald-600' : 'bg-gray-200'
              }`}
            />
          )}

          {/* Step Icon / Circle */}
          <div
            className={`w-9 h-9 rounded-full flex items-center justify-center font-bold z-10 transition-colors ${
              step.isCompleted
                ? 'bg-emerald-600 text-white'
                : step.isCurrent
                ? 'bg-amber-500 text-white animate-pulse'
                : 'bg-gray-200 text-gray-500'
            }`}
          >
            {step.isCompleted ? '✓' : step.step}
          </div>

          {/* Step Labels */}
          <p className="mt-2 text-sm font-semibold text-gray-900 text-center">{step.title}</p>
          {step.timestamp && (
            <span className="text-xs text-gray-500">
              {new Date(step.timestamp).toLocaleDateString()}
            </span>
          )}
        </div>
      ))}
    </div>
  );
};
```

### 2. Rendering the Vertical Activity Checkpoints
```jsx

            {new Date(cp.timestamp).toLocaleString()}
          </time>
        </li>
      ))}
    </ol>
  );
};
```
