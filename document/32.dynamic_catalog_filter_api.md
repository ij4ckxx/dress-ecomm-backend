## 1. Architecture & Core Workflow Overview

The **Dynamic Catalog Filter & Facet Engine** allows storefront users to discover products through rich, multifaceted sidebar filters (Colors, Sizes, Fabrics, Occasions, Price Sliders, Brands, Subcategories, Ratings, and In-Stock toggles).

Unlike static hardcoded filters, all filter choices, counts, and price ranges are dynamically aggregated from active database products and cached with sub-millisecond retrieval.

## 2. Distinction: Attributes vs. Modifiers

In this e-commerce platform architecture:

| Concept | Database Table | Purpose | Where Rendered in Storefront |
| :--- | :--- | :--- | :--- |
| **Attributes & Values** | `Attribute`, `AttributeValue`, `ProductAttributeValue`, `ProductVariantAttribute` | Searchable, reusable specifications: **Color** (*Midnight Black*), **Size** (*S, M, L*), **Fabric** (*Mulberry Silk*), **Occasion** (*Wedding*). | **Sidebar Filters** on Product Listing Pages (PLP) & Catalog Search. |
| **Product Modifiers** | `ModifierGroup`, `ModifierOption`, `CartItemModifier` | Per-product custom add-ons: **Gift Packaging**, **Custom Monogramming / Name Stitching**, **Blouse Customization**. | **Product Detail Page (PDP)** configuration options prior to adding to cart. |

## 3. API Endpoints Overview

| Method | Endpoint | Description | Access | Cache TTL |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/products/filters` | Retrieves dynamic catalog filter options across the storefront or scoped by search/category/brand. | Public | 300s (5 mins) |
| `GET` | `/api/v1/categories/:slug/filters` | Alias endpoint scoped directly to a specific category slug and its descendants. | Public | 300s (5 mins) |
| `GET` | `/api/v1/products` | Updated discovery API supporting multi-select comma-separated attribute filters (both product & variant level). | Public | None / Real-time |

## 4. Detailed Endpoint Specifications

### 4.1 Get Product Filter Options

* **Endpoint:** `GET /api/v1/products/filters`
* **Access:** Public (Guest & Authenticated)
* **Rate Limit:** Standard Client Rate Limiting

#### Query Parameters:

| Parameter | Type | Required | Description | Example |
| :--- | :--- | :--- | :--- | :--- |
| `category` | `string` | No | Slug or UUID of category. Scopes filters to this category and all its descendants. | `category=evening-gowns` |
| `search` | `string` | No | Search keyword. Restricts filter options to products matching the keyword. | `search=silk` |
| `brand` | `string` | No | Brand filter. Scopes options to a specific brand. | `brand=Maison De Élégance` |
| `minPrice` | `number` | No | Optional minimum price boundary. | `minPrice=2000` |
| `maxPrice` | `number` | No | Optional maximum price boundary. | `maxPrice=15000` |

---

### 4.2 Get Category Filter Options (Convenience Alias)

* **Endpoint:** `GET /api/v1/categories/:slug/filters`
* **Access:** Public
* **Path Parameters:**
  * `slug` (*string, required*): The category slug (e.g., `wedding-couture`, `accessories`).
* **Query Parameters:** Supports identical optional query parameters as `/products/filters` (`search`, `brand`, etc.).

## 6. Multi-Select Attribute Filtering in `GET /api/v1/products`

The main product discovery API has been enhanced to handle multi-value selections directly from the sidebar checkboxes:

### Examples:

1. **Filtering by multiple sizes and a color:**
   ```http
   GET /api/v1/products?category=dresses&size=s,m&color=emerald-green&minPrice=2000&maxPrice=10000
   ```
2. **Filtering by multiple colors, sizes, and fabrics:**
   ```http
   GET /api/v1/products?color=midnight-black,crimson-red&size=m,l&fabric=mulberry-silk
   ```
3. **Cross-level resolution:**
   * Direct product attributes (`ProductAttributeValue`, e.g., Color, Fabric, Occasion) AND variant attributes (`ProductVariantAttribute`, e.g., Size, Color) are both evaluated using indexed relational queries.
   * If a product satisfies the criteria either at the root level or via any of its active variants, it is correctly returned.

---

## 7. Performance & Caching Strategy

1. **Hybrid Two-Tier Caching:**
   * Uses Redis where available, falling back to Node.js In-Memory Cache (`node-cache`).
   * Cache Key format: `cache:product:filters:${category}:${search}:${brand}`.
   * **TTL:** 300 seconds (5 minutes).
2. **Atomic Cache Invalidation:**
   * Whenever an administrator adds, updates, or deletes a product, variant, or attribute in the Admin Panel, `purgeCache('cache:product')` flushes all cached product lists and filter facet keys simultaneously.
3. **Zero N+1 Queries:**
   * Resolves attribute values and product groupings in two batch relational queries. Deduplication is performed in O(1) via JavaScript `Set` structures.

## 8. Frontend Integration Guide (Next.js TypeScript)

### 8.1 TypeScript Interfaces

```typescript
export interface FilterCategory {
  id: string;
  name: string;
  slug: string;
  imageUrl: string | null;
  productCount: number;
}

export interface FilterBrand {
  name: string;
  count: number;
}

export interface AttributeFilterValue {
  id: string;
  name: string;
  slug: string;
  count: number;
}

export interface AttributeFilterGroup {
  id: string;
  name: string;
  slug: string;
  values: AttributeFilterValue[];
}

export interface FilterRating {
  rating: number;
  label: string;
  count: number;
}

export interface FilterAvailability {
  inStock: number;
  outOfStock: number;
}

export interface CatalogFilterResponse {
  totalProducts: number;
  category: { id: string; name: string; slug: string } | null;
  priceRange: { min: number; max: number };
  categories: FilterCategory[];
  brands: FilterBrand[];
  attributes: AttributeFilterGroup[];
  ratings: FilterRating[];
  availability: FilterAvailability;
}
```

### 8.2 Frontend Fetch Service Example

```typescript
export const fetchCatalogFilters = async (params?: {
  category?: string;
  search?: string;
  brand?: string;
}): Promise<CatalogFilterResponse> => {
  const query = new URLSearchParams();
  if (params?.category) query.set('category', params.category);
  if (params?.search) query.set('search', params.search);
  if (params?.brand) query.set('brand', params.brand);

  const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/products/filters?${query.toString()}`, {
    next: { revalidate: 300 }, // ISR / SWR cache matching backend TTL
  });

  if (!res.ok) {
    throw new Error('Failed to load catalog filters');
  }

  const json = await res.json();
  return json.data;
};
```
