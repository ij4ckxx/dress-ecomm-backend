## 1. Analysis of `05.front_end_admin_idea.md`

### Strengths Identified
- **Comprehensive Scope:** Covers real-world e-commerce needs (variants, stock ledger, state machine, coupons, feature flags).
- **Relational Integrity:** Good Prisma data model with proper relations between Products, Variants, Orders, and Items.
- **Auditable Design:** Explicit `InventoryTransaction` and `AuditLog` models mirror enterprise standards (Shopify/Medusa).

### Critical Gaps in the Original Blueprint
1. **No Image Upload Pipeline:** The blueprint uses raw URLs (Unsplash). Admin users need to upload actual dress photos from their devices without paying for AWS S3.
2. **Missing Concurrency & Locking:** In flash sales or stock adjustments, simultaneous orders can cause negative inventory without database-level transactions or locks.
3. **Expensive Analytics Queries:** Running `SUM()` and `COUNT()` on raw order tables on every admin dashboard visit will overwhelm free PostgreSQL tiers (e.g., Render/Neon/Supabase 0.25 vCPU). Needs lightweight caching.
4. **Soft Deletes Missing:** Hard-deleting a product or category corrupts past order items or historical customer invoices.
5. **No Data Export Utility:** Real store admins need to export orders to CSV/Excel for local couriers and accounting.

## 2. Bulletproof Admin Security (Preventing Customer Access)

To ensure **no customer can ever access or trigger admin APIs**, we apply **Defense-in-Depth (4 Layers)**:

```
[Incoming Request]
       │
       ▼
[Layer 1: URL Prefix & Router Isolation]   ───► /api/v1/admin/* strictly isolated from client routes
       │
       ▼
[Layer 2: JWT & DB Active Verification]    ───► Validates token signature + verifies account is NOT disabled
       │
       ▼
[Layer 3: Strict Role Guard Middleware]    ───► Rejects any role != SUPER_ADMIN, STORE_ADMIN, STAFF (403)
       │
       ▼
[Layer 4: Granular Action Permission Check] ───► STAFF cannot delete or edit store settings; only SUPER_ADMIN can
       │
       ▼
[Admin Controller Logic]
```

### Key Security Implementations:
1. **Isolated Route Mounting:** Public/customer routes (`/api/v1/client/*` or `/api/v1/products`) and admin routes (`/api/v1/admin/*`) live in separate route trees.
2. **Re-Verification on Sensitive Actions:** Even with a valid token, sensitive operations (refunds, deleting products, changing settings) check the database to confirm the admin has not been demoted or deactivated in real time.
3. **Strict Parameter Validation (Zod):** Strips unexpected fields to prevent Mass Assignment attacks (e.g., a customer trying to send `{ role: "SUPER_ADMIN" }`).
4. **Strict HTTP Status Separation:**
   - Missing/invalid token $\rightarrow$ `401 Unauthorized`
   - Valid customer trying to access admin route $\rightarrow$ `403 Forbidden` (logged immediately to security logs).

## 4. Industry Standards Followed by Top Platforms

1. **Separation of Concerns (Client vs. Admin API):**
   - Public APIs return sanitized, buyer-centric data (hiding profit margins, cost prices, and supplier notes).
   - Admin APIs include `costPrice`, `reservedStock`, internal tags, and supplier SKUs.
2. **Double-Entry Inventory Ledger:**
   - Never just do `stock = stock - 1`. Always pair stock updates with an `InventoryTransaction` record with reasons (`RESTOCK`, `SALE`, `DAMAGE`, `RETURN`).
3. **Idempotency on Critical Endpoints:**
   - Order fulfillment updates and manual stock adjustments accept an `Idempotency-Key` or prevent duplicate clicks on the frontend from deducting double stock.
4. **Soft Deletes (`isArchived` / `deletedAt`):**
   - E-commerce platforms never hard-delete products with order history. Archived products become hidden from the storefront while keeping past invoices intact.
5. **Atomic Database Transactions:**
   - Product creation (creating product + 10 variants + 5 images) is wrapped in `prisma.$transaction([...])`. If one fails, everything rolls back safely.

## 5. Module-by-Module Implementation Roadmap

We will build the admin panel systematically across 8 distinct modules:

```
┌────────────────────────────────────────────────────────────────────────┐
│                      MODULE IMPLEMENTATION PHASES                      │
├──────────────────┬──────────────────┬──────────────────┬───────────────┤
│ Phase 1: Core    │ Phase 2: Catalog │ Phase 3: Sales   │ Phase 4: Ops  │
├──────────────────┼──────────────────┼──────────────────┼───────────────┤
│ Mod 1: Security  │ Mod 2: Category  │ Mod 4: Inventory │ Mod 7: Config │
│ Mod 8: Analytics │ Mod 3: Products  │ Mod 5: Orders    │ Mod 6: Promos │
└──────────────────┴──────────────────┴──────────────────┴───────────────┘
```

### Module 1: Admin RBAC, Security & Dashboard Analytics
- **Scope:** Route isolation (`/api/v1/admin/*`), `requireAdmin` & `requirePermission` middlewares, rate limiting.
- **Analytics:** Overview stats (Revenue, Orders, AOV, Low-stock alerts) with 60-second in-memory caching.
- **Goal:** Unhackable base foundation with instant telemetry.

### Module 2: Category & Curated Collection Engine
- **Scope:** Category CRUD, Subcategory hierarchy, Featured collections, display ordering.
- **Enhancements:** Automatic slugification, duplicate name checks, circular parent checks.

### Module 3: Product & Multi-Variant Catalog Management
- **Scope:** Product CRUD, multi-variant sizing (`S`, `M`, `L`, `XL`), color hex swatches, image handling.
- **Enhancements:** Atomic creation using `prisma.$transaction`, soft-delete/archive toggle, SKU uniqueness validation.

### Module 4: Inventory Tracking & Auditable Stock Ledger
- **Scope:** Flattened inventory list, low-stock threshold triggers, `/inventory/adjust` endpoint.
- **Enhancements:** Strict logging into `InventoryTransaction` for every unit increment/decrement with user audit tracking.

### Module 5: Order Lifecycle, Fulfillment & Courier Tracking
- **Scope:** Order filtering (status, payment, date range), Order Detail view, state transition enforcement.
- **Enhancements:** Enforce state machine (`CONFIRMED` $\rightarrow$ `PROCESSING` $\rightarrow$ `PACKED` $\rightarrow$ `SHIPPED` $\rightarrow$ `DELIVERED`). Add CSV export for packing slips.

### Module 6: Coupons, Discounts & Flash Campaigns
- **Scope:** Coupon CRUD, validity checks (date bounds, min amount, usage quotas, per-user limits).
- **Enhancements:** Usage counters, active/expired toggle, promotional hero banner schedule.

### Module 7: Store Settings, Feature Flags & Audit Logging
- **Scope:** Persist store configuration (active theme, enabled feature flags, shipping thresholds).
- **Enhancements:** Complete `AuditLog` recorder capturing which admin changed settings, prices, or orders.
