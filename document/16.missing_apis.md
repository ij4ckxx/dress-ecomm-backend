### 2.1 Password Reset Flow (High Priority)

#### Problem Statement:
Currently, customers can only change their password while logged in (`PATCH /customer/account/password`). If a customer forgets their password, they are completely locked out of their account.

#### A. Request Password Reset Link
* **Endpoint:** `POST /api/v1/auth/forgot-password`
* **Access:** Public
* **Rate Limit:** 5 requests per 15 minutes per IP

**Request Body:**
```json
{
  "email": "customer@example.com"
}
```

**Business Logic:**
1. Case-insensitively find user by email.
2. If user does not exist, return `200 OK` with generic success message (to prevent email enumeration attacks).
3. If user exists, generate a cryptographically secure random token (e.g. `crypto.randomBytes(32).toString('hex')`).
4. Hash the token with SHA-256 and store in database with 1-hour expiration timestamp (`expiresAt`).
5. Send an HTML email via Nodemailer SMTP with clickable reset link:  
   `${ENV.CLIENT_URL}/reset-password?token=${rawToken}&email=${encodeURIComponent(email)}`

**Response (`200 OK`):**
```json
{
  "success": true,
  "message": "If an account exists with that email, a password reset link has been dispatched."
}
```

---

#### B. Reset Password With Token
* **Endpoint:** `POST /api/v1/auth/reset-password`
* **Access:** Public

**Request Body:**
```json
{
  "email": "customer@example.com",
  "token": "4f9d8a2b1c3e5f7a9d8a2b1c3e5f7a9d",
  "newPassword": "NewSecurePassword123"
}
```

**Business Logic:**
1. Verify token exists, is unused, matches email, and `expiresAt > new Date()`.
2. Hash `newPassword` with `bcryptjs` (salt rounds: 12).
3. Update `user.passwordHash` and mark token as used / delete token.
4. Revoke existing active refresh tokens to force re-login across devices.
5. Send password reset confirmation email via SMTP.

**Response (`200 OK`):**
```json
{
  "success": true,
  "message": "Password has been successfully reset. Please log in with your new credentials."
}
```

### 2.2 Product Reviews & Ratings (Medium Priority)

#### Problem Statement:
Luxury fashion conversion rates increase by up to 270% when customer reviews and ratings are visible. Customers need to see verified reviews and leave their own feedback.

#### A. Fetch Reviews for a Product
* **Endpoint:** `GET /api/v1/products/:id/reviews`
* **Access:** Public
* **Query Params:** `page=1&limit=10&sort=newest|highest|lowest`

**Response (`200 OK`):**
```json

  "success": true,
  "message": "Reviews fetched successfully",
  "data": {
    "summary": {

      "totalReviews": 42,

        "5": 35,

        "3": 2,
        "2": 0,
        "1": 0
      }

    "reviews": [
      {
        "id": "rev_uuid_1",
        "customerName": "Priya S.",
        "rating": 5,
        "title": "Exquisite drape and luxurious fabric!",
        "comment": "The silk blend feels incredible. Fit true to size.",
        "isVerifiedBuyer": true,
        "createdAt": "2026-10-12T14:32:00.000Z"
      }
    ],
    "pagination": { "page": 1, "limit": 10, "totalPages": 5, "total": 42 }
  }
}
```

---

#### B. Submit a Review
* **Endpoint:** `POST /api/v1/products/:id/reviews`
* **Access:** Private (Authenticated Customer)

**Request Body:**
```json
{
  "rating": 5,
  "title": "Bespoke elegance",
  "comment": "Wore this to an evening gala, received countless compliments.",
  "images": ["https://res.cloudinary.com/.../review_photo.jpg"]
}
```

**Business Logic:**
1. Verify customer has a completed order containing this `productId` (marks `isVerifiedBuyer: true`).
2. Prevent duplicate reviews (1 review per customer per product, or update existing).
3. Auto-publish if score is clean or route to `PENDING` queue if profanity is detected.
4. Atomically recalculate and update `product.rating` and `product.reviewCount`.

### 2.3 Order Return / Exchange Request (Medium Priority)

#### Problem Statement:
Customers currently can only cancel orders in `PENDING` status. Once an order is `DELIVERED`, garments that don't fit or are damaged require a formal return/exchange flow.

* **Endpoint:** `POST /api/v1/orders/:orderNumber/return`
* **Access:** Private (Authenticated Customer who owns the order)

**Request Body:**
```json
{
  "items": [
    {
      "orderItemId": "item_uuid_1",
      "quantity": 1,
      "reason": "SIZE_TOO_LARGE",
      "customerNotes": "Requesting size exchange from L to M if possible."
    }
  ],
  "returnType": "REFUND",
  "images": ["https://res.cloudinary.com/.../garment_defect.jpg"]
}
```

**Business Logic:**
1. Order must have `status: 'DELIVERED'`.
2. Delivery timestamp must be within the store's return window (e.g. 7 days from `deliveredAt`).
3. Updates order status to `RETURN_REQUESTED`.
4. Dispatches internal email alert to store operations and confirmation email to customer.

**Response (`201 Created`):**
```json
{
  "success": true,
  "message": "Return request submitted successfully. Our concierge will review it within 24-48 hours.",
  "data": {
    "returnId": "ret_uuid_1",
    "orderNumber": "ORD-20261017-3B6B",
    "status": "RETURN_REQUESTED",
    "createdAt": "2026-10-17T18:00:00.000Z"
  }
}
```

### 3.2 Return & Refund Approvals (Medium Priority)

#### Problem Statement:
Once a customer submits a return request, store managers need to approve reverse pickups, inspect items, and issue refunds.

#### A. Review Return Request
* **Endpoint:** `PATCH /api/v1/admin/orders/:id/return`
* **Access:** Private (Admin with `orders:write`)

**Request Body:**
```json
{
  "action": "APPROVE",
  "internalNotes": "Reverse pickup scheduled with BlueDart",
  "reverseTrackingNumber": "BD-REV-987654"
}
```

---

#### B. Execute Refund & Restock
* **Endpoint:** `POST /api/v1/admin/orders/:id/refund`
* **Access:** Private (Admin with `orders:write`)

**Request Body:**
```json
{
  "amount": 2400.00,
  "restockInventory": true,
  "reason": "Customer return approved and inspected",
  "refundMethod": "ORIGINAL_PAYMENT"
}
```

**Business Logic:**
1. Transitions order to `REFUNDED` and payment to `REFUNDED`.
2. If `restockInventory: true`, atomically increments stock in `ProductVariant` or `Product` and logs an inventory transaction with type `RETURN`.
3. If Razorpay was used, triggers Razorpay Refund API (`razorpay.payments.refund(paymentId, { amount })`).
4. Dispatches refund notification email to customer.

---

### 3.3 Product Review Moderation (Medium Priority)

* **Endpoints:**
  * `GET /api/v1/admin/reviews` — Paginated list with filter: `status=PENDING|APPROVED|REJECTED`
  * `PATCH /api/v1/admin/reviews/:id/status` — Change status: `{ "status": "APPROVED" | "REJECTED" }`
  * `DELETE /api/v1/admin/reviews/:id` — Delete spam/inappropriate review.

## 4. Prisma Schema Additions Required

To support these features, the following models should be added to `prisma/schema/`:

```prisma
// 1. Password Reset Tokens (prisma/schema/auth.prisma)
model PasswordResetToken {
  id        String   @id @default(uuid())
  email     String
  tokenHash String   @unique
  expiresAt DateTime
  createdAt DateTime @default(now())

  @@index([email])
}

// 2. Product Reviews (prisma/schema/catalog.prisma)
enum ReviewStatus {
  PENDING
  APPROVED
  REJECTED
}

model Review {
  id              String       @id @default(uuid())
  productId       String
  product         Product      @relation(fields: [productId], references: [id], onDelete: Cascade)
  userId          String
  user            User         @relation(fields: [userId], references: [id], onDelete: Cascade)
  rating          Int          // 1 to 5
  title           String?
  comment         String
  images          String[]     @default([])
  status          ReviewStatus @default(APPROVED)
  isVerifiedBuyer Boolean      @default(false)
  createdAt       DateTime     @default(now())
  updatedAt       DateTime     @updatedAt

  @@unique([productId, userId])
  @@index([productId, status])
}

// 3. Return Requests (prisma/schema/order.prisma)
enum ReturnStatus {
  REQUESTED
  APPROVED
  REJECTED
  PICKED_UP
  INSPECTED
  REFUNDED
}

model ReturnRequest {
  id                    String       @id @default(uuid())
  orderId               String       @unique
  order                 Order        @relation(fields: [orderId], references: [id], onDelete: Cascade)
  status                ReturnStatus @default(REQUESTED)
  reason                String
  customerNotes         String?
  staffNotes            String?
  reverseTrackingNumber String?
  refundAmount          Decimal?     @db.Decimal(10, 2)
  items                 Json         // Array of { orderItemId, quantity, reason }
  images                String[]     @default([])
  createdAt             DateTime     @default(now())
  updatedAt             DateTime     @updatedAt
}

// 4. Newsletter Subscribers (prisma/schema/settings.prisma)
model NewsletterSubscriber {
  id           String   @id @default(uuid())
  email        String   @unique
  isActive     Boolean  @default(true)
  subscribedAt DateTime @default(now())

  @@index([email])
}

// 5. Inquiries / Contact (prisma/schema/settings.prisma)
model CustomerInquiry {
  id        String   @id @default(uuid())
  name      String
  email     String
  subject   String
  message   String
  isResolved Boolean @default(false)
  createdAt DateTime @default(now())

  @@index([isResolved])
}
```
