## 1. Executive Summary & Architecture

To make the storefront feel instantaneous for customers and eliminate database latency on high-frequency routes (like `/api/v1/auth/me` and `/api/v1/categories`), we have implemented a **Production-Grade Hybrid Caching Engine**:

```
                                  ┌────────────────────────┐
                                  │ Incoming HTTP Request  │
                                  └───────────┬────────────┘
                                              │
                                              ▼
                                    ┌───────────────────┐
                                    │ Cache-First Guard │
                                    └─────────┬─────────┘
                                              │
                      ┌───────────────────────┴───────────────────────┐
                      │                                               │
               [ REDIS_URL Set ]                             [ No REDIS_URL ]
                      │                                               │
                      ▼                                               ▼
          ┌───────────────────────┐                       ┌───────────────────────┐
          │  Remote Cloud Redis   │                       │  High-Speed In-Memory │
          │   (e.g., Upstash)     │                       │     (Node-Cache)      │
          │   1ms - 3ms latency   │                       │      0ms latency      │
          └───────────┬───────────┘                       └───────────┬───────────┘
                      │                                               │
                      └───────────────────────┬───────────────────────┘
                                              │
                                     [ Cache Hit? ]
                                      /          \
                                  YES/            \NO
                                    /              \
                                   ▼                ▼
                         ┌────────────────┐   ┌───────────────────────┐
                         │ Return Cached  │   │ Query Neon PostgreSQL │
                         │ Data Instantly │   │ (Round-trip to Cloud) │
                         └────────────────┘   └───────────┬───────────┘
                                                          │
                                                          ▼
                                              ┌───────────────────────┐
                                              │ Populate Redis/Memory │
                                              │ Cache with TTL        │
                                              └───────────────────────┘
```

### Key Guarantees
1. **Zero Cost & Free-Tier Friendly:** Works immediately without paying any money. Runs out-of-the-box using high-speed in-memory caching.
2. **Crash-Proof & Graceful Fallback:** If Redis is ever unreachable or disconnected, the backend never throws errors to the user; it automatically falls back to in-memory caching.
3. **Event-Driven Invalidation:** When an admin edits a category or a customer changes their profile/password, the cache is instantly purged so data never becomes stale.

## 3. How to Set Up 100% Free Cloud Redis in 60 Seconds (Zero Money / No Card Required)

You do **not** need a credit card. You can create a free serverless Redis instance on **Upstash** (free forever with 10,000 commands per day).

### Step-by-Step Instructions:
1. Go to **[https://upstash.com](https://upstash.com)** and sign in (using GitHub, Google, or email).
2. Click **"Create Database"**.
3. Choose:
   - **Name:** `dress-ecomm-redis`
   - **Type:** Regional
   - **Region:** `ap-southeast-1` (Singapore) — *Select this because your Neon PostgreSQL is in Singapore AWS, keeping latency lowest!*
4. Click **"Create"**.
5. Scroll down to the **"Connect to your database"** section and select the **"Node.js"** or **"ioredis"** tab.
6. Copy the connection string (it begins with `rediss://default:...@...upstash.io:6379`).
7. Paste it into your `.env` file:
   ```env
   REDIS_URL="rediss://default:your_upstash_password@your_endpoint.upstash.io:6379"
   ```
8. When deploying to **Render**, add `REDIS_URL` in Render Environment Variables.

> **Note:** If `REDIS_URL` is omitted, the backend automatically runs in in-memory cache fallback mode with zero configuration needed.

## 4. Cached APIs & Invalidation Rules

### 4.1. User Session & Authentication (`/api/v1/auth/me`)
* **Key:** `auth:user:<userId>`
* **TTL:** `900 seconds` (15 minutes — matches access token lifespan)
* **What it does:** Caches the user profile, role, permissions, and active status in memory/Redis. Eliminates the database query on **every authenticated request** (`authenticate` and `optionalAuthenticate` middlewares).
* **Automatic Invalidation Triggers:**
  - Customer updates profile name, email, or phone (`customer.service.js`).
  - Customer changes avatar (`customer.service.js`).
  - Customer changes password (`customer.service.js`).
  - Customer or admin resets password (`auth.service.js`).
  - User logs out (`auth.service.js`).
  - Admin changes user role, permissions, or deactivates user (`admin/user.service.js`).

---

### 4.2. Category Megamenu & Tree Navigation (`/api/v1/categories`)
* **Keys:**
  - `cache:categories:tree` (Hierarchical megamenu tree)
  - `cache:categories:flat` (Flat category array)
  - `cache:categories:root` (Top-level categories only)
  - `cache:categories:slug:<slug>` (Single category details & breadcrumbs)
* **TTL:** `3600 seconds` (1 hour)
* **What it does:** Serves the store's entire category navigation tree in **0ms–2ms** directly from cache, avoiding recursive product counting and tree building.
* **Automatic Invalidation Triggers:**
  - Admin creates a new category (`admin/category.service.js`).
  - Admin updates a category name, slug, parent, image, or status (`admin/category.service.js`).
  - Admin deletes a category (`admin/category.service.js`).

---

### 4.3. Storefront Global Settings (`/api/v1/settings` & Checkout Pricing)
* **Key:** `cache:store:settings`
* **TTL:** `3600 seconds` (1 hour)
* **What it does:** Caches store name, active currency, free shipping threshold, flat shipping rate, payment method flags, and feature toggles. Accelerates checkout subtotal and shipping calculations.
* **Automatic Invalidation Triggers:**
  - Admin updates store settings (`admin/settings.service.js`).
  - Admin switches storefront theme (`admin/settings.service.js`).
  - Admin toggles feature flags (`admin/settings.service.js`).

---

### 4.4. Admin Dashboard Analytics KPIs
* **Keys:** `analytics:overview:<period>`, `analytics:sales:<period>`, etc.
* **TTL:** `60 seconds`
* **What it does:** Prevents admin dashboard refreshes from hammering heavy aggregation SQL queries on Neon Postgres.

## 5. Developer API Reference (`src/utils/cache.js`)

You can use the unified caching utility anywhere in the backend:

```javascript
import {
  getCache,
  setCache,
  deleteCache,
  purgeCache,
  getOrSetCache,
  invalidateUserSession
} from '../utils/cache.js';

// 1. Get an item from cache
const data = await getCache('my:key');

// 2. Set an item in cache with 5-minute TTL
await setCache('my:key', { name: 'Evening Gown' }, 300);

// 3. Delete a specific key
await deleteCache('my:key');

// 4. Purge all keys matching a prefix
await purgeCache('cache:categories');

// 5. Cache-Aside pattern (Fetch from cache if present, otherwise call async fetcher)
const product = await getOrSetCache(
  `cache:product:${slug}`,
  async () => {
    return await prisma.product.findUnique({ where: { slug } });
  },
  600 // 10 minutes
);

// 6. Invalidate user session
await invalidateUserSession(userId);
```
