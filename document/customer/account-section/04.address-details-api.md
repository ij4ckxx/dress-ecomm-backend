## 2. Address Data Model

The `Address` model is defined in [`prisma/schema/address.prisma`](file:///d:/Projects/dress-ecomm-backend/prisma/schema/address.prisma):

```prisma
model Address {
  id          String   @id @default(uuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  firstName   String
  lastName    String
  company     String?
  address1    String
  address2    String?
  city        String
  state       String
  postalCode  String
  country     String
  phoneNumber String?
  isDefault   Boolean  @default(false)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  @@index([userId])
}
```

## 3. API Endpoints Specification

### 3.1 Create Address

Creates a new saved address for the authenticated customer.

- **Method:** `POST`
- **Path:** `/api/customer/addresses` *(or `/api/v1/customer/addresses`)*
- **Auth Required:** Yes (`Bearer <token>`)

#### Request Headers:
```http
Content-Type: application/json
Authorization: Bearer <jwt_access_token>
```

#### Request Body:
```json
{
  "firstName": "Emma",
  "lastName": "Watson",
  "company": "Warner Bros",
  "address1": "221B Baker Street",
  "address2": "Apt 4B",
  "city": "London",
  "state": "Greater London",
  "country": "United Kingdom",
  "postalCode": "NW1 6XE",
  "phoneNumber": "+44 20 7946 0991",
  "isDefault": true
}
```
*(Note: `pincode` is accepted as an alias for `postalCode`, and `phone` is accepted as an alias for `phoneNumber`).*

#### Success Response (`201 Created`):
```json
{
  "success": true,
  "message": "Address created successfully",
  "data": {
    "address": {
      "id": "b3e0c092-230f-4886-bce7-d6159ba5a623",
      "userId": "7ca5ddb0-c6d7-43b5-bc13-3595a94ce1d4",
      "firstName": "Emma",
      "lastName": "Watson",
      "company": "Warner Bros",
      "address1": "221B Baker Street",
      "address2": "Apt 4B",
      "city": "London",
      "state": "Greater London",
      "postalCode": "NW1 6XE",
      "country": "United Kingdom",
      "phoneNumber": "+44 20 7946 0991",
      "isDefault": true,
      "createdAt": "2026-10-11T14:26:00.000Z",
      "updatedAt": "2026-10-11T14:26:00.000Z"
    }
  }
}
```

#### Error Response - Missing Required Fields (`400 Bad Request`):
```json
{
  "success": false,
  "message": "City is required",
  "error": {
    "code": "VALIDATION_ERROR",
    "details": [
      {
        "field": "city",
        "message": "City is required"
      }
    ]
  }
}
```

### 3.5 Delete Address

Deletes an address owned by the authenticated customer. If the deleted address was default, the next most recent address is automatically promoted to default.

- **Method:** `DELETE`
- **Path:** `/api/customer/addresses/:addressId` *(or `/api/v1/customer/addresses/:addressId`)*
- **Auth Required:** Yes (`Bearer <token>`)

#### Request Headers:
```http
Authorization: Bearer <jwt_access_token>
```

#### Success Response (`200 OK`):
```json
{
  "success": true,
  "message": "Address deleted successfully"
}
```

#### Error Response - Not Found or Belongs to Another User (`404 Not Found`):
```json
{
  "success": false,
  "message": "Address not found",
  "error": {
    "code": "ADDRESS_NOT_FOUND"
  }
}
```

## 4. Multi-Tenant Isolation & Security Guarantees

1. **Owner-Scoped Queries:** All Prisma queries use composite matching `where: { id: addressId, userId: req.user.id }`.
2. **Preventing ID Injection:** The `userId` is supplied directly from `req.user.id` (extracted and verified from the cryptographically signed JWT). Any `userId` or `customerId` supplied in the request body is discarded.
3. **Foreign Access Rejection:** If Customer A attempts to read, edit, or delete an address belonging to Customer B, the API returns `404 Not Found` rather than `403 Forbidden`, preventing resource enumeration attacks.
4. **Order Immutability:** Historical orders store a frozen snapshot of shipping addresses as JSON (`Order.shippingAddress Json`). Deleting or updating a saved customer address has zero impact on past orders or invoices.

## 5. Future Admin Configurability Blueprint

Field rules are declared in `ADDRESS_FIELD_CONFIG` within [`src/validators/address.validator.js`](file:///d:/Projects/dress-ecomm-backend/src/validators/address.validator.js#L6-L20):

```javascript
export const ADDRESS_FIELD_CONFIG = {
  firstName: { required: true, minLength: 1, maxLength: 50 },
  lastName: { required: true, minLength: 1, maxLength: 50 },
  company: { required: false, maxLength: 100 },
  address1: { required: true, minLength: 1, maxLength: 255 },
  address2: { required: false, maxLength: 255 },
  city: { required: true, minLength: 1, maxLength: 100 },
  state: { required: true, minLength: 1, maxLength: 100 },
  postalCode: { required: true, minLength: 2, maxLength: 20 },
  country: { required: true, minLength: 1, maxLength: 100 },
  phoneNumber: { required: false, minLength: 7, maxLength: 20, pattern: /^[+]?[0-9\s\-()]{7,20}$/ },
};
```

When building the Admin Panel configuration engine in a future phase:
- Admin can toggle required vs. optional fields via `StoreConfig`.
- The database schema keeps nullable columns (`String?`) for optional fields so no schema migrations are needed when settings change.
- Ownership checks (`userId`) and structural constraints remain strictly enforced.
