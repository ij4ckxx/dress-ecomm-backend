Review your previous customer-side audit report and proceed with the remaining work, with the following scope restrictions.

## 2. Fix Critical Existing Issues First

### A. Customer Registration Security

The audit identified a possible privilege-escalation vulnerability in customer registration.

Inspect the actual implementation and fix it so that public registration always assigns the `CUSTOMER` role, regardless of any role supplied in the request body.

Ensure existing admin accounts, admin authentication, and legitimate registration flows continue working.

### B. Refresh Token API

The audit reports that refresh-token business logic exists but its controller and route are missing.

Inspect the existing refresh-token implementation, token rotation, cookie configuration, and authentication middleware. If the route is genuinely missing, expose it using the existing architecture.

Ensure refresh tokens are securely validated, revoked or rotated according to the existing design, and cannot be reused improperly.

Do not duplicate existing refresh-token logic.

## 3. Audit and Complete Other Customer-Side Functionality

Inspect the existing code and determine whether the following functionality is complete and correctly integrated:

* Registration, login, logout, and session/token refresh
* Customer account details and password changes
* Customer address CRUD
* Category browsing and navigation
* Product listing, search, filtering, sorting, and pagination
* Product detail pages, variants, modifiers, prices, and stock information
* Cart operations, quantity updates, item removal, and cart clearing
* Guest cart persistence and cart merging after login
* Cart and item metafields
* Public store settings required by the storefront
* Public collections/lookbooks, if required by the existing frontend
* Product reviews and ratings, if required by the existing frontend

Do not assume a feature is complete merely because its database model, service, or route exists. Check the actual implementation, validation, authorization, error handling, and integration.

For features that are already working, preserve them. For missing or broken features within this scope, explain the issue and propose the smallest safe fix.

## 4. Pricing and Cart Review

The previous audit reported that cart pricing does not include complete coupon, tax, and shipping calculations.

Inspect the existing implementation and identify what is required for the storefront's cart summary to display accurate pricing.

Do not implement checkout, payment processing, or order creation as part of this task. Do not invent tax rates, shipping policies, or discount rules. Identify any business decisions that require my confirmation.

## 5. Database and Admin Compatibility

Before modifying database schemas or existing APIs:

* Inspect existing Prisma models, migrations, and related services.
* Reuse existing models and functions wherever possible.
* Identify any potential breaking changes.
* Explain the impact and proposed solution before applying risky changes.
* Preserve admin functionality and existing data.
* Do not perform destructive migrations or delete existing data.

## 6. Development Rules

* Follow the existing project structure and coding conventions.
* Use function-based programming only; do not use classes.
* Write optimized, reusable, and maintainable code.
* Avoid duplicate logic, unnecessary dependencies, and overengineering.
* Add or update tests using the existing testing framework.
* Do not modify unrelated features.
