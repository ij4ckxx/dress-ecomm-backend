---

## 📌 Root Cause Analysis: Why Orders API was Failing

Before running the test suite, we identified why the Orders API was throwing an error:
1. **Prisma Client Desynchronization:** The authentication middleware was selecting `permissions` on the `User` model, but `@prisma/client` had not been re-generated. Running `npx prisma generate` resolved the underlying database query error.
2. **Endpoint Alias:** In addition to the standard route `GET /api/v1/orders`, we also registered the alias `GET /api/v1/customer/orders` so that both endpoint patterns work interchangeably.
