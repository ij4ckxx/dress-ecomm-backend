## 1. Executive Summary & Architecture Overview

The checkout system in `dress-ecomm-backend` is modeled after BigCommerce's transactional checkout architecture and implemented strictly using **functional programming (zero classes)** in adherence to `CODE_STRUCTURE.md`.

It provides an end-to-end, resilient customer checkout flow supporting both **Online Card / UPI Payments via Razorpay** and **Cash on Delivery (COD)** with admin verification.

```
+-----------------------------------------------------------------------------------------------------------------------+
|                                              CUSTOMER CHECKOUT FLOW                                                   |
+-----------------------------------------------------------------------------------------------------------------------+
|                                                                                                                       |
|   +--------------------------+        +--------------------------+        +---------------------------------------+   |
|   | 1. Validate Coupon       | -----> | 2. Pre-Checkout Summary  | -----> | 3. Place Order                        |   |
|   | POST /coupons/validate   |        | POST /checkout/summary   |        | POST /checkout                        |   |
|   +--------------------------+        +--------------------------+        +---------------------------------------+   |
|                                                                                               |                       |
|                                                  +--------------------------------------------+                       |
|                                                  |                                                                    |
|                                                  v                                                                    v
|                                        [paymentMethod: 'RAZORPAY']                                         [paymentMethod: 'COD']
|                                                  |                                                                    |
|                                                  v                                                                    v
|                                       +----------------------+                                            +-----------------------+
|                                       | Razorpay Modal       |                                            | Order Placed (PENDING)|
|                                       +----------------------+                                            | Admin Concierge Alert |
|                                                  |                                                        +-----------------------+
|                                                  v                                                                    |
|                                       +----------------------+                                                        v
|                                       | 4. Verify Signature  |                                            +-----------------------+
|                                       | POST /payments/verify|                                            | 5. Order Confirmation |
|                                       +----------------------+                                            | GET /orders/:no/conf. |
|                                                  |                                                        +-----------------------+
|                                                  +------------------------------------------------------------>       ^
|                                                                                                                       |
+-----------------------------------------------------------------------------------------------------------------------+
```

## 2. API Endpoints Reference

### 2.1 Validate Coupon Code
* **Endpoint:** `POST /api/v1/coupons/validate`
* **Authentication:** Optional (`Bearer <accessToken>`). If authenticated, checks per-user usage limits.
* **Purpose:** Validates coupon eligibility in real time before checkout submission, checking validity window, minimum order spend, total usage limits, and customer-specific usage caps.

#### Request
```http
POST /api/v1/coupons/validate HTTP/1.1
Host: localhost:5000
Content-Type: application/json
Authorization: Bearer <accessToken>
```

```json
{
  "code": "LUXE10",
  "subtotal": 5000
}
```

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `code` | `string` | **Yes** | Alphanumeric coupon code (case-insensitive) |
| `subtotal` | `number` | **Yes** | Current cart subtotal in rupees ($\ge 0$) |

#### Success Response (`200 OK`)
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Coupon applied successfully",
  "data": {
    "isValid": true,
    "code": "LUXE10",
    "discountType": "PERCENTAGE",
    "discountValue": 10,
    "discountAmount": 500,
    "minOrderAmount": 1000,
    "maxDiscountAmount": 1000,
    "description": "10% off luxury gowns"
  }
}
```

#### Error Responses
| Status | Code | Description |
| :--- | :--- | :--- |
| `404 Not Found` | `COUPON_NOT_FOUND` | Coupon code does not exist |
| `400 Bad Request` | `COUPON_INACTIVE` | Coupon is disabled |
| `400 Bad Request` | `COUPON_NOT_STARTED` | Campaign has not started yet |
| `400 Bad Request` | `COUPON_EXPIRED` | Campaign has ended |
| `400 Bad Request` | `COUPON_USAGE_EXCEEDED` | Global redemption cap reached |
| `400 Bad Request` | `COUPON_USER_LIMIT_EXCEEDED` | Customer has exceeded per-account limit |
| `400 Bad Request` | `MIN_ORDER_NOT_MET` | Cart subtotal is below `minOrderAmount` |

### 2.2 Pre-Checkout Summary & Calculation
* **Endpoint:** `POST /api/v1/checkout/summary`
* **Authentication:** **Required** (`Bearer <accessToken>`)
* **Purpose:** Recalculates authoritative line item prices, verifies real-time inventory for all items, calculates 12% GST luxury garment tax, applies dynamic shipping rules, and returns an itemized bill breakdown.

#### Request
```http
POST /api/v1/checkout/summary HTTP/1.1
Host: localhost:5000
Content-Type: application/json
Authorization: Bearer <accessToken>
```

```json
{
  "shippingAddressId": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "couponCode": "LUXE10"
}
```

### 2.3 Place Order
* **Endpoint:** `POST /api/v1/checkout`
* **Authentication:** **Required** (`Bearer <accessToken>`)
* **Purpose:** Atomically verifies inventory, decrements product/variant stock, creates immutable order snapshots, clears the customer cart, logs inventory audit ledgers, and initializes payment.

#### Request
```http
POST /api/v1/checkout HTTP/1.1
Host: localhost:5000
Content-Type: application/json
Authorization: Bearer <accessToken>
```

```json
{
  "shippingAddressId": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "billingAddressSameAsShipping": true,
  "paymentMethod": "RAZORPAY",
  "couponCode": "LUXE10",
  "customerNotes": "Please ring the bell upon arrival."
}
```

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `shippingAddressId` | `string (UUID)` | Optional | Saved address ID (or pass `shippingAddress` inline) |
| `shippingAddress` | `object` | Optional | Inline shipping address payload |
| `billingAddressSameAsShipping` | `boolean` | Optional | Defaults to `true`. If `false`, `billingAddress` is required |
| `billingAddress` | `object` | Optional | Inline billing address payload |
| `paymentMethod` | `string` | **Yes** | Either `"RAZORPAY"` or `"COD"` |
| `couponCode` | `string` | Optional | Promo coupon code |
| `customerNotes` | `string` | Optional | Delivery instructions or concierge notes |

### 2.4 Verify Razorpay Payment Signature
* **Endpoint:** `POST /api/v1/payments/verify`
* **Authentication:** **Required** (`Bearer <accessToken>`)
* **Purpose:** Validates the cryptographic HMAC-SHA256 signature returned by Razorpay Checkout. Upon verification, the order is updated to `CONFIRMED`, `paymentStatus` is updated to `COMPLETED`, and an order confirmation email is sent.

#### Request
```http
POST /api/v1/payments/verify HTTP/1.1
Host: localhost:5000
Content-Type: application/json
Authorization: Bearer <accessToken>
```

```json
{
  "orderId": "e8a0d798-dc58-45e0-811d-ef1f6c04f981",
  "razorpayOrderId": "order_mock_1791827927172_782qd",
  "razorpayPaymentId": "pay_rzp_9876543210",
  "razorpaySignature": "2f4e9185a06c278c772db..."
}
```

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `orderId` | `string (UUID)` | **Yes** | Internal database order UUID |
| `razorpayOrderId` | `string` | **Yes** | Razorpay Order ID |
| `razorpayPaymentId` | `string` | **Yes** | Razorpay Payment ID returned from client SDK handler |
| `razorpaySignature` | `string` | **Yes** | Cryptographic HMAC signature returned by Razorpay |

#### Success Response (`200 OK`)
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Payment verified and order confirmed successfully",
  "data": {
    "verified": true,
    "order": {
      "id": "e8a0d798-dc58-45e0-811d-ef1f6c04f981",
      "orderNumber": "ORD-20261012-FUU4",
      "status": "CONFIRMED",
      "paymentStatus": "COMPLETED",
      "paymentMethod": "RAZORPAY",
      "totalAmount": 9518.88
    }
  }
}
```

#### Error Responses
| Status | Code | Description |
| :--- | :--- | :--- |
| `400 Bad Request` | `PAYMENT_VERIFICATION_FAILED` | HMAC signature mismatch or tampered response |
| `404 Not Found` | `ORDER_NOT_FOUND` | Order ID does not match an order owned by this user |

## 3. What Was Changed & Hardened Across the Codebase

While implementing and testing the checkout pipeline, several key improvements and fixes were made:

### 3.1 Neon Serverless PostgreSQL Transaction Timeout Resilience (`P2028`)
* **Problem:** Interactive Prisma transactions (`prisma.$transaction(async (tx) => { ... })`) were timing out with error `P2028: Transaction already closed` because the default timeout is only 5,000 ms. Neon serverless latency over international routes caused round trips to exceed 5 seconds.
* **Fix Applied:** 
  1. Pre-fetched static resources (such as `storeConfig`) outside the transaction boundaries.
  2. Passed explicit options `{ maxWait: 10000, timeout: 30000 }` to all `prisma.$transaction` calls across the system:
     - `src/services/client/checkout.service.js` (order creation and payment verification)
     - `src/services/client/address.service.js` (address create, update, delete)
     - `src/services/client/cart.service.js` (add item, update item, merge guest cart)
     - `src/services/admin/order.service.js` (status update, dispatch tracking, order cancellation)

### 3.2 Prisma Schema Field Alignments
* **`InventoryTransaction`:** Corrected data creation payload to supply required fields `quantityChange` (`Int`), `previousStock` (`Int`), and `newStock` (`Int`), which were previously missing from ledger recordings.
* **`CouponUsage`:** Corrected field mapping to `discountApplied` (`Decimal`) matching the schema definition.
* **`Coupon`:** Corrected property reference to `maxDiscountAmount` (`Decimal?`) from `maxDiscount`.

### 3.3 COD Admin Concierge Review & Email Notification Hooks
* **COD Admin Notification:** On COD order placement, an instant alert email is dispatched to the store admin (`sendCodAdminAlertEmail`).
* **COD Admin Approval:** In `src/services/admin/order.service.js`, when an admin approves a COD order (`PENDING` $\rightarrow$ `CONFIRMED`), a customer notification is dispatched via `sendCodStatusUpdateEmail({ order, approved: true })`.
* **COD Admin Rejection & Stock Restoration:** When an admin rejects or cancels an order, `cancelOrderService` restores product and variant inventory with `RETURN` entries in `InventoryTransaction` and notifies the customer via `sendCodStatusUpdateEmail({ order, approved: false, reason })`.

### 3.4 Email & Razorpay Services
* **`src/services/payment/razorpay.service.js`:** Created with standard Razorpay SDK integration, fallback sandbox emulation for testing, and HMAC-SHA256 signature verification.
* **`src/services/notification/email.service.js`:** Created using Nodemailer with graceful fallback logging when SMTP credentials are not configured in `.env`.
* **`src/config/env.js`:** Registered `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET`.

## 4. Frontend Integration Checklist

```
Step 1: On Cart / Checkout page load, optionally call POST /api/v1/coupons/validate when user enters a promo code.
Step 2: Call POST /api/v1/checkout/summary with shippingAddressId (or inline address) + couponCode to display authoritative totals.
Step 3: When customer clicks "Pay Now / Place Order", submit POST /api/v1/checkout.
Step 4A (If RAZORPAY):
   - Receive response.data.razorpay { orderId, keyId, amount, currency }.
   - Open Razorpay Standard Checkout SDK modal:
     const rzp = new Razorpay({
       key: razorpay.keyId,
       amount: razorpay.amount,
       currency: razorpay.currency,
       order_id: razorpay.orderId,
       handler: function(response) {
         // Send response.razorpay_order_id, response.razorpay_payment_id, response.razorpay_signature
         // to POST /api/v1/payments/verify
       }
     });
     rzp.open();
Step 4B (If COD):
   - Redirect directly to confirmation screen.
Step 5: Load GET /api/v1/orders/:orderNumber/confirmation to render the order success page.
```
