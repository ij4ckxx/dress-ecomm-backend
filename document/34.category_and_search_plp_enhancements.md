# 34. Category & Search PLP Enhancements and Filter Parity

This document details the enhancements made to the client catalog services (`category.service.js` and `product.service.js`) to support dynamic filtering, folder-based category navigation, color swatch previews, and smart button actions in the frontend.

---

## 1. Objectives & Summary of Changes

1. **Category Products Filter Parity (`category.service.js`)**:
   - Upgraded `getCategoryProducts` to support the full filter matrix available in `product.service.js`.
   - Added support for `subcategory` scoping: filters products to a specific child category under the current parent category.
   - Added `brand` filtering: supports single brand name or comma-separated lists (`?brand=Royal Silks of India,Zari & Silk Heritage`).
   - Added `inStock` filtering: filters products where `stockQuantity > 0` or any active variant has `stockQuantity > 0`.
   - Added `rating` filtering: filters products with `rating >= minRating`.
   - Added dynamic catalog attributes filtering: supports arbitrary attribute filters like `color=emerald-green,midnight-black`, `size=m,l`, `fabric=pure-katan-silk`, `occasion=royal-wedding-bridal`.

2. **Luxury Product Card Data Enrichment (`category.service.js` & `product.service.js`)**:
   - **Secondary Image**: In addition to `thumbnail` (`images[0]`), queries take 2 images so `secondaryImage` (`images[1]`) is returned for hover reveal animation.
   - **Color Swatches (`colors`)**: Extracts distinct active variant colors `[{ name: "Emerald Green", slug: "emerald-green" }, ...]` for rendering interactive color swatch dots on product cards.
   - **Brand, Rating, Reviews**: Returns `brand`, `rating`, and `reviewCount` on all product cards.
   - **Smart Action Determination (`requiresConfiguration`)**:
     - `hasVariants = variants.length > 0`
     - `hasModifiers = modifierGroups.length > 0`
     - `requiresConfiguration = hasVariants || hasModifiers`
     - When `requiresConfiguration === true`, UI renders **"Select Options"** linking to `/product/[slug]`.
     - When `requiresConfiguration === false`, UI renders **"Add to Cart"** button directly on the card.

## 2. API Endpoints Reference

### 1. `GET /api/v1/categories?tree=true`
Returns all categories in a hierarchical nested tree structure (`children: [...]`), along with direct `productCount`. Used to render the interactive Category Folder Tree directory.

### 2. `GET /api/v1/categories/:slug/products`
Retrieves paginated and filtered products for a specific category and all its descendants.

**Query Parameters:**
| Parameter | Type | Description |
|-----------|------|-------------|
| `page` | number | Page number (default: 1) |
| `limit` | number | Products per page (default: 20) |
| `sort` | string | Sort criteria: `newest`, `price_asc`, `price_desc`, `name_asc`, `name_desc`, `bestselling`, `rating`, `best_deals` |
| `subcategory` | string | Child category slug or ID to narrow results |
| `brand` | string | Brand name or comma-separated brand list |
| `minPrice` | number | Minimum price threshold |
| `maxPrice` | number | Maximum price threshold |
| `inStock` | boolean | Set `true` to filter items currently in stock |
| `rating` | number | Minimum star rating (e.g. `4` for 4★ & above) |
| `search` | string | Keyword query across name, description, and brand |
| `[attribute]` | string | Dynamic attribute slug and comma-separated value slugs (e.g., `color=red,black&size=m,l`) |

### 3. `GET /api/v1/categories/:slug/filters`
Returns dynamic aggregation counts scoped to the current category:
- `categories`: direct subcategories with `productCount`
- `brands`: available brands with live product counts
- `attributes`: Color, Fabric, Occasion, Size values with counts
- `priceRange`: `min` and `max` effective bounds
- `availability`: `inStock` and `outOfStock` counts

### 4. `GET /api/v1/products` & `GET /api/v1/products/filters`
Used for general catalog browsing and keyword searches (`/search?q=...`), returning the identical enriched product structure and aggregations.

## 3. Query Parameter Normalization (`q` and `search`)
- **Fix for Parameter Collision**: Previously, backend dynamic attribute filtering treated unrecognized query parameters as attribute slugs. When frontend passed `q` in addition to `search`, the catalog service checked for an attribute named `q`, producing 0 matches.
- **Resolution**:
  - `product.service.js` & `category.service.js` have added `'q'` to `KNOWN_QUERY_KEYS` and `KNOWN_KEYS`.
  - Both services now accept either `query.search` or `query.q` transparently.
  - `fetchProducts` and `fetchProductFilters` in the frontend normalize incoming parameters so only `search` is forwarded to the API.
