# Module 05: Order Lifecycle, Fulfillment & Courier Tracking API

> **Module:** 05 - Order Lifecycle, Fulfillment & Courier Tracking  
> **Audience:** Frontend Development Team (`/admin/orders`)  
> **Base URL:** `/api/v1/admin/orders`  
> **Auth Required:** `Authorization: Bearer <accessToken>`  
> **Required Permissions:**  
> - Read: `orders:read`  
> - Status / Shipping / Notes: `orders:write`  
> - Cancel Order: `orders:cancel`  
> *(Automatic root bypass for `SUPER_ADMIN`)*  

---

## 1. Overview & State Machine Architecture

The Order Fulfillment Engine orchestrates fashion order processing from initial placement through atelier tailoring, packing, courier dispatch, and final delivery:

### 1.1. Fulfillment State Machine

```
[ PENDING ] ───► [ CONFIRMED ] ───► [ PROCESSING ] ───► [ PACKED ] ───► [ SHIPPED ] ───► [ OUT_FOR_DELIVERY ] ───► [ DELIVERED ]
     │                │                  │                 │                                                        │
     ▼                ▼                  ▼                 ▼                                                        ▼
[ CANCELLED ]    [ CANCELLED ]      [ CANCELLED ]     [ CANCELLED ]                                          [ RETURN_REQUESTED ]
                                                                                                                    │
                                                                                                                    ▼
                                                                                                               [ RETURNED ]
                                                                                                                    │
                                                                                                                    ▼
                                                                                                               [ REFUNDED ]
```

### 1.2. Key Rules & Guarantees
1. **Strict Transition Rules:**
   - Orders follow a natural progression: `PENDING` $\rightarrow$ `CONFIRMED` $\rightarrow$ `PROCESSING` $\rightarrow$ `PACKED` $\rightarrow$ `SHIPPED` $\rightarrow$ `OUT_FOR_DELIVERY` $\rightarrow$ `DELIVERED`.
   - Cancellation is permitted during `PENDING`, `CONFIRMED`, `PROCESSING`, and `PACKED`. Orders that are already `SHIPPED` or `DELIVERED` cannot be cancelled directly (must proceed through `RETURN_REQUESTED`).
2. **Double-Entry Stock Restitution:**
   - When an order is cancelled via `POST /api/v1/admin/orders/:id/cancel`, the backend atomically re-credits inventory back to the respective garment variants and products, recording a `RETURN` transaction in the `InventoryTransaction` ledger.
3. **Audit History & Timeline:**
   - Every status advance is immutably logged into `OrderStatusHistory` with timestamp, previous/new status, staff attribution (`changedBy`), and optional comments.
4. **Courier Manifest & CSV Export:**
   - Single-click CSV export endpoint (`/export/csv`) converts filtered orders into standard courier manifests and packing slips for local shipping partners (e.g. BlueDart, Delhivery, FedEx).

## 2. API Endpoints Specification

### 2.1. List Orders (Faceted Filters & Summary Counters)
Retrieves paginated orders for the main fulfillment table with status filtering, date range searches, and KPI summary counters.

- **Endpoint:** `GET /api/v1/admin/orders`
- **Headers:** `Authorization: Bearer <token>`
- **Query Parameters:**
  - `page`: Page number (Default: `1`)
  - `limit`: Items per page (Default: `20`, Max: `100`)
  - `search`: Searches orderNumber, customerName, customerEmail, customerPhone, and trackingNumber
  - `status`: `"ALL"` (default), `"PENDING"`, `"CONFIRMED"`, `"PROCESSING"`, `"PACKED"`, `"SHIPPED"`, `"OUT_FOR_DELIVERY"`, `"DELIVERED"`, `"CANCELLED"`, `"RETURN_REQUESTED"`, `"RETURNED"`, `"REFUNDED"`
  - `paymentStatus`: `"ALL"` (default), `"PENDING"`, `"COMPLETED"`, `"FAILED"`, `"REFUNDED"`
  - `paymentMethod`: `"ALL"` (default), `"RAZORPAY"`, `"STRIPE"`, `"COD"`
  - `startDate`: ISO datetime start (e.g. `2026-10-01T00:00:00Z`)
  - `endDate`: ISO datetime end (e.g. `2026-10-10T23:59:59Z`)
  - `minAmount`: Minimum total order amount
  - `maxAmount`: Maximum total order amount
  - `sort`: `"newest"` (default), `"oldest"`, `"total_asc"`, `"total_desc"`
- **Example Request:**
  `GET /api/v1/admin/orders?page=1&limit=10&status=CONFIRMED&sort=newest`

### 2.3. Advance Order Status
Advances an order along the fulfillment state machine (e.g. from `CONFIRMED` $\rightarrow$ `PROCESSING` or `PROCESSING` $\rightarrow$ `PACKED`).

- **Endpoint:** `PATCH /api/v1/admin/orders/:id/status`
- **Headers:** `Authorization: Bearer <token>`, `Content-Type: application/json`
- **Request Body:**
```json
{
  "status": "PROCESSING",
  "comment": "Transferred to bespoke tailoring department for finishing"
}
```
- **Response `200 OK`:**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Order #ORD-20261008-9823 status updated to PROCESSING",
  "data": {
    "id": "ord_uuid_101",
    "orderNumber": "ORD-20261008-9823",
    "status": "PROCESSING",
    "updatedAt": "2026-10-10T01:45:00.000Z"
  }
}
```
- **Error Response `400 Bad Request` (Illegal state transition):**
```json
{
  "success": false,
  "statusCode": 400,
  "message": "Illegal transition from 'PENDING' to 'DELIVERED'. Allowed: CONFIRMED, CANCELLED",
  "error": {
    "code": "ILLEGAL_STATUS_TRANSITION"
  }
}
```

### 2.6. Cancel Order (With Automatic Stock Restitution)
Cancels an order with a mandatory reason, automatically restores garment inventory back to the warehouse, and records an unalterable audit ledger entry.

- **Endpoint:** `POST /api/v1/admin/orders/:id/cancel`
- **Headers:** `Authorization: Bearer <token>`, `Content-Type: application/json`
- **Permission Required:** `orders:cancel` (`SUPER_ADMIN` or `STORE_ADMIN` only)
- **Request Body:**
```json
{
  "reason": "Customer requested cancellation prior to dispatch"
}
```
- **Response `200 OK`:**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Order #ORD-20261008-9823 successfully cancelled",
  "data": {
    "id": "ord_uuid_101",
    "orderNumber": "ORD-20261008-9823",
    "status": "CANCELLED",
    "cancelReason": "Customer requested cancellation prior to dispatch",
    "cancelledAt": "2026-10-10T01:50:00.000Z"
  }
}
```
- **Error Response `400 Bad Request` (Attempting to cancel delivered order):**
```json
{
  "success": false,
  "statusCode": 400,
  "message": "Cannot cancel an order that has already been delivered",
  "error": {
    "code": "ORDER_DELIVERED"
  }
}
```

### 2.7. Export Orders Manifest to CSV
Generates a downloadable CSV manifest with order and recipient details, ready for courier partner pickups and warehouse packing slips.

- **Endpoint:** `GET /api/v1/admin/orders/export/csv`
- **Headers:** `Authorization: Bearer <token>`
- **Query Parameters:** Supports identical query filters as `GET /api/v1/admin/orders` (`status`, `paymentStatus`, `startDate`, `endDate`).
- **Response `200 OK`:**
  - `Content-Type: text/csv`
  - `Content-Disposition: attachment; filename="orders-manifest-2026-10-10.csv"`
- **CSV Headers Generated:**
  `Order Number,Order Date,Customer Name,Customer Email,Customer Phone,Address,City,Postal Code,Order Status,Payment Status,Payment Method,Items,Total Units,Total Amount (INR),Courier Partner,Tracking Number`

## 3. Frontend Implementation & UI Guidelines

### 3.1. Fulfillment Summary Cards
Map `meta.summary` from `GET /api/v1/admin/orders` directly to top dashboard KPI metrics:
- **Total Revenue:** Format as `₹{summary.totalRevenue.toLocaleString()}`
- **Confirmed Orders:** `summary.confirmedCount` (Actionable: Needs atelier assignment)
- **In Processing / Packed:** `summary.processingCount + summary.packedCount` (Needs dispatch)
- **Dispatched:** `summary.shippedCount` (In courier transit)

### 3.2. Order Status Badge Palette
| Status | Recommended Tailwind / CSS Classes | Meaning |
| :--- | :--- | :--- |
| `PENDING` | `bg-amber-50 text-amber-700 border-amber-200` | Awaiting checkout payment capture |
| `CONFIRMED` | `bg-blue-50 text-blue-700 border-blue-200` | Accepted by store; ready to pick |
| `PROCESSING` | `bg-indigo-50 text-indigo-700 border-indigo-200` | Under tailoring / atelier prep |
| `PACKED` | `bg-purple-50 text-purple-700 border-purple-200` | Boxed with garment bag & sealed |
| `SHIPPED` | `bg-sky-50 text-sky-700 border-sky-200` | Handed over to courier |
| `OUT_FOR_DELIVERY` | `bg-cyan-50 text-cyan-700 border-cyan-200` | On delivery van |
| `DELIVERED` | `bg-emerald-50 text-emerald-700 border-emerald-200` | Successfully delivered to client |
| `CANCELLED` | `bg-rose-50 text-rose-700 border-rose-200` | Cancelled & inventory restored |
| `RETURN_REQUESTED` | `bg-orange-50 text-orange-700 border-orange-200` | Customer requested return |
| `RETURNED` | `bg-zinc-100 text-zinc-700 border-zinc-300` | Returned to warehouse |
| `REFUNDED` | `bg-teal-50 text-teal-700 border-teal-200` | Payment refunded to customer |

### 3.3. Action Modals
1. **"Advance Status" Action Button:**
   - Detects current order status and presents only legal target transitions as dropdown options.
   - Includes optional comment textarea.
2. **"Assign Shipment" Modal:**
   - Courier partner input (with quick-select badges: `BlueDart`, `Delhivery`, `FedEx`, `DHL`).
   - AWB Tracking number field.
   - Optional estimated delivery date picker.
3. **"Cancel Order" Confirmation Modal:**
   - Restricted to `SUPER_ADMIN` and `STORE_ADMIN`.
   - Displays clear warning: *"Cancelling will automatically restore garment stock quantities in the warehouse."*
   - Requires cancellation reason before the confirm button becomes enabled.
