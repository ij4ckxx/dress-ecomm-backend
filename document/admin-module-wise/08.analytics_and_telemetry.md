# Module 08: Performance Analytics & In-Memory Telemetry API

> **Module:** 08 - Performance Analytics & In-Memory Telemetry  
> **Audience:** Frontend Development Team (`/admin`, `/admin/analytics`)  
> **Base URL:** `/api/v1/admin/analytics`  
> **Auth Required:** `Authorization: Bearer <accessToken>`  
> **Required Permission:** `analytics:read` (`SUPER_ADMIN` or `STORE_ADMIN`)  

---

## 1. Overview & Architecture

This module provides high-speed, aggregated business intelligence, sales telemetry, and fulfillment health metrics for the luxury admin dashboard:

1. **60-Second In-Memory Caching (Zero Cloud Cost):**
   - Running live SQL aggregations (`SUM()`, `COUNT()`, `GROUP BY`) on raw order tables on every admin page refresh can quickly exhaust free-tier serverless PostgreSQL compute (Neon/Render).
   - All analytics endpoints are backed by an in-memory cache layer (`node-cache`) with a **60-second TTL**.
   - API responses include metadata indicating whether data was served from cache (`meta.fromCache: true/false`).
2. **Comparative Period Telemetry:**
   - Supports time windows: `7d`, `30d` (default), `90d`, and `year`.
   - Automatically computes percentage delta (`revenueChangePct`, `ordersChangePct`, `aovChangePct`) by comparing against the prior equivalent period.
3. **Fulfillment Pipeline & Inventory Telemetry:**
   - Real-time pipeline counters (`activeOrdersCount`, `pendingDispatchCount`).
   - Warehouse safety metrics (`lowStockCount`, `outOfStockCount`).
4. **Time-Series Charting & Top Products:**
   - Daily and monthly bucketed time-series for revenue line and bar charts.
   - Best-selling couture garments ranked by units sold and revenue generated.

## 2. API Endpoints Specification

### 2.1. Dashboard Overview KPIs
Retrieves high-level performance cards with comparative growth percentages and warehouse counters.

- **Endpoint:** `GET /api/v1/admin/analytics/overview`
- **Headers:** `Authorization: Bearer <token>`
- **Query Parameters:**
  - `period`: `"7d"`, `"30d"` (default), `"90d"`, `"year"`
- **Example Request:**
  `GET /api/v1/admin/analytics/overview?period=30d`
- **Response `200 OK`:**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Dashboard analytics overview fetched successfully",
  "data": {
    "period": "30d",
    "totalRevenue": 1428500.00,
    "revenueChangePct": 18.4,
    "ordersCount": 84,

    "lowStockCount": 6,
```

### 2.5. Instant Analytics Cache Purge
Flushes in-memory cache to guarantee that subsequent queries immediately recalculate fresh telemetry against the database.

- **Endpoint:** `POST /api/v1/admin/analytics/cache/purge`
- **Headers:** `Authorization: Bearer <token>`
- **Response `200 OK`:**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Analytics telemetry cache successfully cleared"
}
```

## 3. Frontend Implementation & UI Guidelines

### 3.1. Top KPI Metric Cards
Render four primary hero cards:
1. **Total Revenue:**
   - Display: `₹{data.totalRevenue.toLocaleString()}`
   - Trend Badge:
     - If `revenueChangePct >= 0`: Green pill with upward arrow `+18.4% vs last period`
     - If `revenueChangePct < 0`: Red pill with downward arrow `-5.2% vs last period`
2. **Total Orders:**
   - Display: `{data.ordersCount}`
   - Subtitle: `Active Pipeline: {data.activeOrdersCount}`
3. **Average Order Value (AOV):**
   - Display: `₹{data.averageOrderValue.toLocaleString()}`
   - Trend Badge: `+5.7%`
4. **Urgent Inventory Alert:**
   - Display: `{data.lowStockCount} Low / {data.outOfStockCount} Out`
   - Pill: Amber warning pill with direct link to `/admin/inventory?status=LOW_STOCK`

### 3.2. Period Selector Tabs
Provide a button group for the user:
- `7 Days` $\rightarrow$ `?period=7d`
- `30 Days` (Active default) $\rightarrow$ `?period=30d`
- `90 Days` $\rightarrow$ `?period=90d`
- `Year` $\rightarrow$ `?period=year`
On click, refresh `GET /overview` and `GET /revenue-chart` with the selected period.

### 3.3. Cache Invalidation & Refresh Button
- Next to the period selector, include a subtle refresh button with tooltip: *"Refresh Telemetry"*.
- Clicking calls `POST /api/v1/admin/analytics/cache/purge` followed by refetching overview and chart data.
